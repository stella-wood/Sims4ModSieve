# 冲突评级与拆分标准

本文是检测结果评级与页面归属的权威产品标准。相关需求、设计和后续实现按本文对齐；CLI 字段约定保留在本文，暂待实现对齐。

## 一、冲突颜色评级

**按「对游戏意味着什么」分**，用颜色分轻重，一个颜色对应一个总标签。

| 颜色 | 标签 | 标准 | CLI `severity` |
| --- | --- | --- | --- |
| 红 | **异常** | 确定跟正常状态不一样 | `abnormal` |
| 黄 | **有隐患** | 现在不一定出事，但埋着风险 | `risk` |
| 绿 | **不影响** | 不影响游戏正常运行，不用处理 | `no_effect` |
| 灰 | **未分析** | 程序没分析完 | `incomplete` |

### 各项归哪级

| 组标签 | 内容描述 | 评级 | 说明 |
| --- | --- | --- | --- |
| 资源覆盖冲突 | 资源内容不同、互相覆盖 | 异常 | |
| 资源覆盖冲突 | 两个 mod 同时覆盖同一个原版资源 | 异常 | 后加载的生效，另一个的改动整个没了 |
| 脚本冲突 | 脚本模块撞名（mod 之间，或盖住游戏自带模块） | 异常 | |
| 层级过深 | 脚本放太深（超过 Mods 下一层） | 异常 | 游戏不加载脚本 |
| 文件损坏 | 文件坏了，游戏也读不了 | 异常 | |
| 脚本版本错误 | 脚本 Python 版本对不上 | 异常 | 确定跑不了 |
| 疑似同一 mod | 组内互相资源覆盖超过基线 | 有隐患 | 留最新版 |
| 重复文件 | 重复 | 有隐患 | |
| 重复模块（脚本） | 包含同名模块且内容相同的脚本 | 有隐患 | |
| 合集包含 | 合集文件与被包含文件 | 有隐患 | |
| 可能失效 | 游戏更新后可能失效 | 有隐患 | 覆盖的原版资源这次被改了（#19 #20 #21） |
| 资源缺失 | Tray 缺 CC | 有隐患 | 要先有本体索引（#12 #28） |
| 文件位置错误 | 位置不对（如 Tray 文件放进 Mods） | 有隐患 | |
| 覆盖原版资源 | 覆盖原版 | 不影响 | Default 替换、调参 mod 的正常用法 |
| 同一 mod | 同一个 mod 自己的几个文件互相配合覆盖 | 不影响 | |
| — | 程序读不了、没比完 | 未分析 | 跟「文件坏了游戏也读不了」分开 |

### 新功能进来怎么放

- 确定不正常 → 异常
- 可能出事 → 有隐患
- 完全没事 → 不影响
- 我们查不了 → 未分析

注：不要将所有检查正常的 package 文件放进「不影响」层级，仅展示 Default 替换、调参 mod。

### CLI 相关字段（待对齐）

- `severity`
- `certainty`：`confirmed`（确定的）/ `possible`（可能的）。结论分两档，跟 `severity` 分开存。
- `kind`：具体是什么，如 `resource_conflict`、`script_collision`、`not_loaded`、`duplicate`、`base_override`

## 二、页面怎么分

**判断方法：解释这条结果时，要不要指着另一个文件（或游戏本体）说「是因为它」？要 → 冲突检测；不要 → 健康检查。**

| 页面 | 查什么 | 包括 |
| --- | --- | --- |
| 冲突检测 | 文件之间（至少两方） | 资源撞号、脚本模块撞名、mod 跟本体（覆盖原版、两个 mod 盖同一个原版、盖住游戏自带模块） |
| 健康检查 | 文件自己 | 坏文件、脚本太深、Python 版本、位置不对、更新后可能失效、Tray 缺 CC |
| 重复检测 | 同一个东西重复 | |

- 「更新后可能失效」玩家感受到的是「这个 mod 旧了」，放健康检查。
- 每个页面里都可以出现四种颜色。
