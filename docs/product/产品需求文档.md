# Sims 4 Mod Sieve 产品需求

> 更新日期：2026-11-09
> 0.15 及之前的完整版本见 [archive/产品需求文档-0.15.md](../archive/产品需求文档-0.15.md)

## 1. 产品是什么

Windows 上《模拟人生 4》的本地 Mod 整理与排错工具。不需要登录，扫描在本机完成，不上传任何文件。

首页两个入口：**重复文件检测**、**Mod 冲突检测**。后续可提供「一键体检」，依次运行两者、分标签展示结果；当前尚未实现。

两项功能互不依赖，只共用当前 Mods 位置，各自维护来源列表、勾选状态和当前结果；一项失败或取消不影响另一项，不要求先运行其中一项才能进入另一项。当前没有持久化扫描历史。来源变更与会话规则见 [Agent 指南](../../AGENTS.md#73-结果会话)。

## 2. 设计原则

- 界面按玩家要做的事组织，不按后端模块组织。后端可以共用扫描、解析等模块，但不能让它们变成玩家必须先完成的步骤。
- 默认用玩家能懂的话。TGI、哈希、调用栈放在可展开的详情或导出报告里。
- 能用合理默认直接满足玩家意图时，直接做，不展示系统推理过程。
- 扫描只读。修改文件只发生在玩家明确选择并确认之后。
- 「没发现问题」和「没能分析」分开统计，读不了的文件不算健康。
- 不承诺静态检查能发现所有运行时问题。

## 3. 重复文件检测

### 3.1 范围

- 可添加任意多个文件夹并逐个勾选／取消；取消勾选不删除记录。
- 默认推荐 Mods 文件夹，但可以只扫外部目录（下载、备份、待整理等）。
- 每个结果文件显示完整路径和它来自哪个扫描文件夹。

### 3.2 判定

内容完全相同（整文件 SHA-256）即为重复。文件名、目录、修改时间不参与判定。

### 3.3 父目录和子目录同时选择

例如同时选了 `D:\Mods` 和 `D:\Mods\家具`：

1. 每个实际文件只读一次。
2. `家具` 是重点范围；`Mods` 中除 `家具` 以外的部分是参照范围。
3. 「家具 ↔ 其他位置」的跨范围重复排在最前、默认展开；两边各自内部的重复作为次级结果折叠。
4. 同一组只出现在一个分区。

这一推断不向玩家解释，只体现在结果顺序上。

### 3.4 一键勾选

只勾选、不删除。每组保留恰好一份，其余勾上。保留顺序：

1. Mods 内的文件优先于外部目录
2. 目录层级更深的优先
3. 仍并列时按路径稳定地选一个（同一次结果中不会来回变化）

勾选后玩家可任意调整，再点「删除所选」才执行。组复选框在「按建议勾选」或「整组全选」时都显示为选中。

只用于整文件相同的组，不用于冲突结果。

## 4. Mod 冲突检测

基础排查只扫描冲突页来源列表中启用的文件夹，可以只扫描外部目录或选定子目录。按单个文件或分类选择范围尚未实现。

入口进入「基础排查」「报错日志分析」「健康性检查」「二分排查」四功能总览；只有基础排查已接入扫描，其余入口显示「尚未开放」。页面结构见 [冲突检测页面方案](../design/冲突检测页面方案-v1.md#页面范围)。

检测结果的评级与功能归属以 [冲突评级与拆分标准](冲突评级与拆分标准.md) 为准。当前入口布局及结构问题展示尚未全部对齐，不能据此改变产品分类。

### 4.1 健康性检查（尚未开放）

独立健康检查尚未开放；已有的结构与读取问题由基础排查的未完成入口展示。后续各项检查逐步加入，每份报告列出本次实际运行了哪些检查，没运行的不能显示为「通过」。

| 检查 | 现状 |
|---|---|
| package 文件或索引结构检查 | 底层预检已实现；工具读取失败与游戏无法加载的判定仍需区分 |
| `.ts4script` 结构与条目读取 | 底层已实现；损坏条目不影响同归档正常模块 |
| 脚本放得太深（Mods 下超过一层子文件夹，游戏不加载） | 待做 |
| Tray（图库里的人家、地块）用到了哪些 Mod | 待做，需求说明另附 |
| Tray 缺了哪些 CC | 需要游戏本体资源清单，暂缓 |
| 依赖缺失、资料片需求、版本不兼容 | 待调研 |

### 4.2 基础排查（已接入界面）

对所选范围：

- 比较多个 package 中的同一资源，按 v2 文件关系展示资源覆盖冲突、疑似同一 mod、合集包含；脚本按顶层包名及参与文件集合展示模块卡片。
- 复用整文件重复扫描，在冲突会话内展示重复文件卡，不替换独立重复检测的结果。
- 未完成分析按文件汇总，区分局部读取失败、整文件未分析和来源范围问题。
- 已证明的 package 包含只在冲突结果中提示，不接入独立重复检测的删除建议。

分组与技术详情规则见 [分组方案 v2](../design/冲突检测分组方案-v2.md)，数据契约与扫描流程见 [冲突检测页面方案](../design/冲突检测页面方案-v1.md#基础排查)。冲突页已提供单文件回收站删除、禁用／启用、忽略及文件关系查看，不判断具体生效文件。

覆盖原版或互相覆盖不自动算作有害。没有做过游戏内实验之前，不推断哪个文件最终生效。

原版覆盖、多个 mod 覆盖同一原版资源，以及脚本盖住游戏自带模块的检查尚未实现，均需要游戏本体索引。

### 4.3 报错日志分析（尚未开放）

读取游戏原生的 `lastException`、`lastUIException`；装了 MCCC 时额外读取 `mc_lastexception.html`。MCCC 不是必需。

展示证据和可信度。不能只凭文件修改时间断定是哪个 Mod 引起的。

动手实现前需要一批真实报错文件作样本。

### 4.4 二分排查（尚未开放）

静态检查找不出原因时使用：

1. 软件把选定范围内的 Mod 分成两半，禁用其中一半。
2. 玩家进游戏看问题还在不在，回来点「还在」或「没了」。
3. 软件记住结果，继续缩小范围，直到定位到一个或几个文件。

可以把健康检查、冲突检测中的嫌疑文件排在前面，减少轮数。

要求：

- 任何时候可以中止；中止或完成后都能一键把本次禁用的文件全部恢复原样。
- 进度保存在 Mods 文件夹以外，软件关掉再打开可以继续。
- 禁用方式见 6.2。

### 4.5 结果分级

统一采用 [冲突评级与拆分标准](冲突评级与拆分标准.md) 的四种评级与独立确定性约定，不再使用旧的四级处理优先级和四档可信度。

当前 WPF 使用「异常／有隐患／未分析」筛选，绿色结果及工具读不了与游戏读不了的区分尚待对齐。任何评级都不自动删除或禁用文件。CLI 字段暂待对齐。

## 5. 一键体检

依次运行重复检测和冲突检测。开始前显示两边各自将使用的范围，结果分两个标签。一项失败，另一项的结果照常保留。

## 6. 文件操作

### 6.1 删除

- 只删除玩家明确指定的单个文件或当前勾选的实际文件。删除进入 Windows 回收站，不提供永久删除。
- 确认窗只有一句「确定删除所选文件？」和「否／是」。
- 执行前按 [文件快照核对规则](../release/file-operation-safety.md) 后台复核；变了就不删，要求重新扫描。
- 部分失败时逐项报告，不报成全部成功。
- 检测页提供最近一次删除批次的「撤回」；跨批次、跨重启的历史恢复由设置页管理，规则见 [删除与忽略](../design/设置页面方案-v1.md#删除与忽略)。

### 6.2 禁用

保留 Mod 文件，通过改名暂时停用，随时可以恢复。当前入口位于设置的「删除与忽略 → 已禁用」及冲突文件行右键菜单，替代原隔离区；具体后缀、清单、确认和恢复规则见 [设置页面方案 · 已禁用](../design/设置页面方案-v1.md#已禁用)。二分排查与自动 Mod 分组尚未接入。

### 6.3 不做

修复 Mod、编辑 package 内容、自动下载或更新 Mod、自动删除或禁用文件。

## 7. 联网与隐私

- 扫描、分析和报告生成在本机完成，不需要登录，不上传 Mod、路径、日志或报告。
- 程序启动时后台向 GitHub 检查一次最新版本，仅有新版本时显示首页更新图标；点击后由系统浏览器打开发布页，不自动下载安装。检查失败不打扰扫描，也不写入工具错误诊断。
- 工具错误诊断与扫描计时在设置页显示、复制时脱敏；磁盘日志和导出报告可能保留完整路径，分享前需检查。文件行与技术详情仍显示实际路径。

## 8. 设置页（第一版）

- 文件夹：共用默认 Mods 位置与独立 Tray 位置；选择后立即保存，支持打开目录及确认后采用系统默认候选。Tray 检测尚未开放。
- 删除与忽略：已禁用文件、长期回收站记录与持久化文件忽略名单。
- 诊断与反馈：查看本工具运行与启动错误，复制脱敏诊断信息，打开日志目录，前往 GitHub 反馈。
- 关于：实际版本、项目主页、MIT 许可证、第三方声明。

页面、保存边界、诊断脱敏和默认目录规则见 [设置页面方案](../design/设置页面方案-v1.md)。设置页更改默认位置保留两种检测的现有会话。

尚未实现：删除与禁用方式设置、游戏安装位置、扫描排除、深色模式。更新检查已在启动流程实现，设置页没有检查开关。

## 9. 平台与测试

正式支持：Windows 上的 Sims 4 PC 版；本机可访问的文件夹。

尚未验证：macOS、Linux／Wine／Proton、主机版、网络共享目录、其他代际的模拟人生。

功能状态按证据标注：自动测试通过／本机真实测试通过／多用户验证通过。代码能运行不等于正式支持。

扩大测试时需覆盖：不同 Windows 版本、EA app 与 Steam、被 OneDrive 重定向的文档目录、中文与长路径、机械硬盘、上千个 Mod 的集合、损坏文件与旧版脚本。
