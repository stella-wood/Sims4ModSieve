# 冲突检测分组方案 v2

> 2026-10-12 · 取代《冲突检测页面方案-v1》中「结果怎么分组、怎么显示」的部分；左侧检查范围、扫描与取消流程沿用 v1。
> 依据：当前 Mods 真机统计（1380 个 package、181,203 条资源）的四份只读调研报告，见文末「数据依据」。

## 1. 为什么要改

v1 按「一样资源（TGI）一组」或「两个文件一对」显示，颜色只看内容相同还是不同。在真实 Mods 上：

- 按资源分 25,104 组，按文件对分 59,488 对，玩家没法看。
- 同一个 mod 的新旧两版，改过的每一样都标红，看起来和真冲突一样。
- 工具元数据、NameMap 这类每个文件都带一份的资源制造了大量假警报。

v2 改为先判断**文件之间是什么关系**，按关系出卡片，颜色表示**玩家要不要处理**。

## 2. 名词

| 名词 | 含义 |
|---|---|
| 资源集合 S(f) | 文件 f 中排除第 3 节类型后的全部 TGI |
| 撞号 | 两个以上文件含有同一个 TGI |
| 内容版本 | 同一 TGI 在不同文件里按解压后内容分组，内容一样为同一版本 |
| 包含 | S(A) ⊆ S(B) 且 \|S(A)\| < \|S(B)\| |
| 双向重合度 | \|S(A) ∩ S(B)\| ÷ max(\|S(A)\|, \|S(B)\|) |

## 4. 关系判定

对至少撞号一次的文件对，按以下顺序判定，**一对文件只进一种关系**：

1. **合集包含**：A 被 B 包含，且 \|S(A)\| ≥ 最小文件门槛（正式默认 3）。
2. **疑似同一 mod**：不属于 1，且双向重合度 ≥ 判定线（默认 50%，设置可改）。
3. **资源覆盖冲突**：不属于 1、2，且本文件对至少有一个撞号 TGI 内容不同。A、B 相同而 C 不同时，A–B 不算资源覆盖冲突；不能用原始 Comparison 的全组版本数、Verdict 或 IsComplete 代替逐对事实。
4. **隐藏**：不属于 1、2，且所有撞号 TGI 内容都相同（零碎重叠，不影响游戏）。

### 4.1 合集包含（卡片）

把所有包含关系按 B（较大的文件）合并：**一个 B 一张卡**。

每张卡计算：
- 被包含文件数；其中每个 A 标「已被包含」（A 的全部资源内容与 B 中相同）或「存在不同」（至少一样内容不同）。
- 合集独有数 = \|S(B) − ∪S(A)\|，即删除合集会丢失的资源数。
- 一个 A 可被多个 B 包含（当前 151 个），在每个 B 的卡里都出现。

### 4.2 疑似同一 mod（卡片）

成组规则：**组内任意两个文件对都已经判为「疑似同一 mod」，不靠中间文件传递连接**。仅重合度达线不足以加入：优先判为合集包含的文件对不能用于疑似成组。

算法（已在真实数据上验证，最大组 10 个文件）：
- 候选对按双向重合度降序，同分按共有数降序，再按路径排序。
- 两个都未入组 → 成立新组；一个已入组 → 只有它与该组每个成员均属于疑似关系才加入；两个都已入组 → 不合并。
- 每个文件最多在一个组，组至少两个文件。

### 4.3 资源覆盖冲突（卡片）

一张卡 = 在抢同一批 TGI 的那几个文件。正式规则为 `ByExactSharedKeySet`：以已分类为资源覆盖冲突的文件对为单元，共有 TGI 集合完全相同才合卡，成员取文件并集，不改变四种关系。

`ByPair` 保留为对照规则，每个覆盖对一张卡。`BySharedKeyOverlap` 保留为显式实验选项：以覆盖文件对为单元，按共有键集合的交集数除以较大集合数计算重合度，阈值须显式提供。按重合度降序、交集数降序、稳定路径顺序贪心成组，加入需与每个既有单元达线，已形成的组不合并；落单文件对仍单独成卡，合卡成员取文件并集。

红卡 TGI 只取本卡收录的覆盖关系的共有键并集，作为圈卡依据键；已属于疑似同一 mod 或合集包含的文件对不贡献红卡显示计数。

每个文件计算：
- 撞 N 样：本卡收录的覆盖关系中，涉及该文件的共有 TGI 并集大小（**按文件各自计算**，同一张卡里可以不同）；这些关系内内容一致的撞号也计入，重复记录不重复计数。
- 独有 M 样：完整资源集合差 \|S(f) − ∪S(卡内其他文件)\|，即它自己有、其他文件都没有的资源数；删除它会丢失这些。不用资源总数减红卡撞 N，卡内其他关系的共有资源仍须扣除。

### 4.4 性能

分组只用扫描结果里的完整索引数量和内容比较，不再读硬盘、不再解压；只处理排除后的撞号文件对，包括纯一致的局部重叠。改判定线、合集门槛或圈卡规则后直接 Build 重算。调整 NameMap 开关从同一份原始报告重新 Prepare，不需要重新扫描。

## 5. 卡片

### 5.1 收起时一行

```
∨ ● 第 N 组　类型 · N 个文件　　　　　　　👁(划线)
```

| 关系 | 圆点 | 状态 | 标签 |
|---|---|---|---|
| 资源覆盖冲突 | 砖红 | 需查看 | 资源覆盖冲突 |
| 疑似同一 mod | 琥珀黄 | 可整理 | 疑似同一 mod |
| 合集包含 | 琥珀黄 | 可整理 | 合集包含 |

- 不写具体 package 名，只写文件数。
- 排序：红在前，黄在后；同色内按文件数降序。
- 「第 N 组」序号在一次扫描结果内固定，筛选、忽略、展开不重排。身份由类型、成员及本卡依据构成，跳转不依赖列表下标。删除使成员变化而产生新卡时分配新号，恢复原卡沿用原号。新扫描重新编号。
- 标题右侧只保留忽略按钮，不重复写需查看／可整理。黄色层级先列重复文件卡，再列其他黄色卡。

### 5.2 展开后

统一顺序：**一句话说明 → 文件列表 → 右下角「技术详情」**。不显示卡底建议或收起时的关系说明。所有展开行均为同一虚拟化列表中的兄弟项。

每个文件一行：文件名、所在文件夹、修改时间、大小，右侧依次为打开所在文件夹、仅本组忽略、移到回收站（先确认）。图标使用矢量，透明矩形宿主承担命中，悬停变紫且无底色。路径包含文件名，Tooltip 保留全文。

**资源覆盖冲突**
- 说明：「这 N 个 mod 都在替换同一批东西（M 样<种类>），游戏只会用其中一份。」
- 文件行追加「撞 N 样 · 独有 M 样」。内容版本相同的文件归在一起，小字「以下 N 个内容相同」。
- 独有为 0 只表示本卡其他文件覆盖其资源集合，不自动选择或删除。

**疑似同一 mod**
- 说明：「这几个文件大部分内容相同，像同一个 mod 装了几份。」有不同时追加「有 N 样不一样，疑似新旧版本」。
- 修改时间最新的文件标「最新」。
- 最新标识只展示修改时间，不改变 Core 建议保留策略。

**合集包含**
- 说明：「<合集名> 里装着 N 个你另外单独放着的文件：X 个已被包含，Y 个存在不同。它还有 M 样只有合集里有。」
- 第一行是合集本身，标「合集」，追加「独有 M 样」。下面是被包含的文件，每行标「已被包含」或「存在不同」。
- 合集自身先显示，底色略深，与其他文件留出间隔；不在卡底另列建议。

### 5.3 技术详情

卡片上写「有多少」，技术详情写「具体是哪些」，给要用 Sims 4 Studio 修改的人看。

- 一张表，每行一个 TGI：编号（Type:Group:Instance 十六进制，可复制）· 种类名 · 每个文件里是第几版本（内容相同用同一版本号）。
- 疑似同一 mod、合集包含列出卡内全部撞号依据；内容一致仍显示同一版本号。
- 资源覆盖冲突：列出被抢的那一批。
- 种类名来自对照表；没有可靠来源的显示编号，不凭记忆填。
- 技术详情在当前组下方独立展开／收起，不使用弹窗。表格无底色、边框或内部滚动条，继承现有技术字体，10 DIP，长 TGI 与文件名换行。文件列超过六列时分段展示，分段仍在主列表内虚拟化。
- 底部「复制详情」：复制本卡全部依据、各文件版本、原始路径、哈希与解压大小。共享依据可跳转其他卡，本卡独有依据不省略。剪贴板写入失败时显示“复制未完成”。

## 6. 读取失败

不作为组。单独一块放在卡片列表最下面：

一条未排除资源读取失败，整个文件退出本次分组，其他已确认资源也不让它继续参加；退出文件与原始结构化原因独立保留，不形成第五种关系。索引失败、文件版本不稳定同样退出。第三个文件退出后，仍保留其余成功文件对的逐对事实。缺失完整类型数量、比较或版本证据时明确报告输入缺数据，不猜测也不补读文件。

```
有 N 个文件没读成，以下结果不包括它们
文件名　　原因　　📁
```

原因用人话：文件损坏建议重新下载 / 格式暂不支持 / 单条资源过大 / 扫描期间文件被修改 / 无法访问。

点顶部「未完成」标签直接滚到这一块。

## 7. 筛选

- 顶部横栏沿用全部 / 需查看 / 可整理 / 未完成的位置和样式。
- 漏斗弹窗：状态（需查看 / 可整理 / 未完成）、种类（资源覆盖冲突 / 疑似同一 mod / 合集包含 / 重复文件 / 脚本）、「显示已忽略」（默认不勾）。筛选生效时漏斗显示小点。
- 脚本冲突沿用现有判定，按同样的红黄规则出卡。

## 8. 忽略

| 位置 | 作用范围 | 再次提醒的条件 |
|---|---|---|
| 组标题行的 👁 | 整组 | 成员集合或该类卡的忽略键依据 TGI 集合发生变化 |
| 文件行的忽略按钮 | 仅控制当前卡中该文件行的显示，不删除关系或重建卡；全部文件都忽略后仍保留组 | 同上 |

- 默认隐藏已忽略组和文件；“显示已忽略”可同时显示二者并取消忽略。文件与所属组同时被忽略只淡化一次；组号、组标题和文件名改为普通字重。
- 忽略仅保存在当前结果会话，页面往返保留，新扫描或清空本页来源重置，不新增持久化格式。
- 红卡键使用成员路径身份和本卡圈卡依据键；合集、疑似卡使用卡内全部撞号键。直接调用 `ConflictIgnoreKeyBuilder.Build`，路径身份包含卷或共享根，按 Windows 大小写语义处理。显示折叠与筛选不改变键或计数。

### 整文件重复与导航

主动开始冲突扫描后，使用本页明确启用的来源调用现有 `IDuplicateRunService`，与索引、资源内容及脚本阶段共用取消流程。整文件大小与 SHA256 相同才建立黄色“重复文件”卡；读取失败、版本不匹配或证据不足的文件不据此标为重复。结果属于冲突会话，不覆盖独立重复页。

哈希报告的 `file-changed-during-hash`，或整文件重复证据中的文件戳与资源／脚本扫描文件戳不一致，均记录为结构化的文件变化原因；后者使用 `hash-scan-stamp-mismatch`。已确认变化的路径从本次缓存分组输入、资源／脚本文件对及重复卡中退出，关系弹层、技术详情和删除／撤回重建沿用该排除；其余稳定文件继续按缓存事实成组。不补读磁盘。其他哈希读取错误不视为文件变化，脚本条目级失败仍不排除同归档的正常模块。

每个整文件重复组各出一张卡。疑似卡的全部成员属于同一个已确认整文件重复组时，展示只保留重复卡；Core 原始关系判定不变。混合疑似组保留真实关系，卡内完全重复副本折为代表行，保留实际路径引用；仅资源相同、整文件不同或缺少整文件证据时仍保留疑似卡，不折为副本。显示组数、跨卡入口和关系弹层的出现卡片数均以实际展示卡片为准。代表文件和建议保留调用 `DuplicateSelectionService`。重复卡首个可见文件不重复写“内容完全相同”，其余文件保留该注释，卡内没有技术详情。

重复卡说明显示本次重复组总数与“去重复检测一键处理 →”。链接只导航；已有大小、哈希及路径匹配的独立重复组时可定位，不检测、不导入、不覆盖结果、不改变来源或勾选。返回冲突页保留状态。

### 文件关系

点击文件名打开以该文件为主题的弹层。用 `GroupsByFile` 找卡，再按卡内真实直接文件对取关联文件，同卡无直接关系的成员不混入。每个关联文件一行，多种关系与组入口合并；包含方向按关联文件相对主文件显示“包含✦”或“被✦包含”，辅助阅读保留完整含义。

主文件名旁仅在有包含关系时显示浅紫底的紫色自绘标记。主文件显示文件名、含文件名的路径、修改时间和大小，不显示主文件组跳转；关联文件只显示名称、关系和路径，名称局部使用附带 OFL 的思源黑体 CN Light。现有文件行仍用等线 14 DIP，其他已有字体直接复用，不更改公共资源。

主文件的副本说明独立显示“存在N份副本，完全相同”，关联文件保留自己的副本折叠入口。副本展开只列完整路径，第一条右侧提供“去第N组 →”；主文件下方实线，主文件副本行的下方虚线仅展开时出现。

弹层参考宽度 620 DIP，内容少时自然收短，居中偏上；正常窗口可完整显示主文件下方四行关联文件。更多关系和展开副本使用内部虚拟化列表滚动，关闭与页脚始终可用。小窗口按可用区域适配。开关保留轻微旋转缩放，Escape、关闭和遮罩均可关闭，关闭后恢复焦点。组跳转关闭弹层，必要时恢复筛选、显示忽略组，展开并按卡片身份定位。

### 删除、撤回和缓存更新

单行删除只提交该行路径及扫描文件戳，复用 `IFileActionService` 和现有确认窗，不连带副本或其他组成员。只按服务返回的成功路径更新；失败文件保留。

后台从缓存的 `PackageConflictGroupingInput` 移除成功路径后调用正式 `Build`，同步重建卡、计数、重复卡与跨卡关系；不重新读文件或扫描 Mods。撤回仅恢复服务确认成功的路径。独立重复页已有涉及这些路径的结果同步更新，来源、扫描会话和勾选仍独立。

共享删除服务只保留最近一次批次，记录所属页面、冲突会话引用及重复页 generation；清空或重扫所属页面清掉对应撤回记录，另一页的新结果不会被旧撤回覆盖。
