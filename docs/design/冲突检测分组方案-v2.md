# 冲突检测分组方案 v2

> 2026-10-12 · 取代《冲突检测页面方案-v1》中「结果怎么分组、怎么显示」的部分；左侧检查范围、扫描与取消流程沿用 v1。
> 依据：当前 Mods 真机统计（1380 个 package、181,203 条资源）的四份只读调研报告，见文末「数据依据」。

## 1. 为什么要改

v1 按「一样资源（TGI）一组」或「两个文件一对」显示，颜色只看内容相同还是不同。在真实 Mods 上：

- 按资源分 25,104 组，按文件对分 59,488 对，玩家没法看。
- 同一个 mod 的新旧两版，改过的每一样都标红，看起来和真冲突一样。
- 工具元数据、NameMap 这类每个文件都带一份的资源制造了大量假警报。

v2 改为先判断**文件之间是什么关系**，按关系出卡片，颜色表示**玩家要不要处理**。

## 2. 名词

| 名词 | 含义 |
|---|---|
| 资源集合 S(f) | 文件 f 中排除第 3 节类型后的全部 TGI |
| 撞号 | 两个以上文件含有同一个 TGI |
| 内容版本 | 同一 TGI 在不同文件里按解压后内容分组，内容一样为同一版本 |
| 包含 | S(A) ⊆ S(B) 且 \|S(A)\| < \|S(B)\| |
| 双向重合度 | \|S(A) ∩ S(B)\| ÷ max(\|S(A)\|, \|S(B)\|) |

## 4. 关系判定

对至少撞号一次的文件对，按以下顺序判定，**一对文件只进一种关系**：

1. **合集包含**：A 被 B 包含，且 \|S(A)\| ≥ 最小文件门槛（待定，见第 12 节）。
2. **疑似同一 mod**：不属于 1，且双向重合度 ≥ 判定线（默认 50%，设置可改）。
3. **覆盖冲突**：不属于 1、2，且至少有一个撞号 TGI 的内容版本数 ≥ 2。
4. **隐藏**：不属于 1、2，且所有撞号 TGI 内容都相同（零碎重叠，不影响游戏）。

### 4.1 合集重复（卡片）

把所有包含关系按 B（较大的文件）合并：**一个 B 一张卡**。

每张卡计算：
- 被包含文件数；其中每个 A 标「已被包含」（A 的全部资源内容与 B 中相同）或「存在不同」（至少一样内容不同）。
- 合集独有数 = \|S(B) − ∪S(A)\|，即删除合集会丢失的资源数。
- 一个 A 可被多个 B 包含（当前 151 个），在每个 B 的卡里都出现。

### 4.2 疑似同一 mod（卡片）

成组规则：**组内任意两个文件的双向重合度都 ≥ 判定线，不靠中间文件传递连接**。

算法（已在真实数据上验证，最大组 10 个文件）：
- 候选对按双向重合度降序，同分按共有数降序，再按路径排序。
- 两个都未入组 → 成立新组；一个已入组 → 只有它与该组每个成员都达线才加入；两个都已入组 → 不合并。
- 每个文件最多在一个组，组至少两个文件。

### 4.3 覆盖冲突（卡片）

一张卡 = 在抢同一批 TGI 的那几个文件。**圈卡规则待定**（第 12 节），先用「被抢的 TGI 集合高度重合的文件放一张卡」做试验。

每个文件计算：
- 撞 N 样：它在这张卡里被抢的 TGI 数（**按文件各自计算**，同一张卡里可以不同）。
- 独有 M 样：它自己有、其他文件都没有的资源数；删除它会丢失这些。

### 4.4 性能

分组只用扫描结果里的目录和内容版本，不再读硬盘、不再解压；只处理撞号文件对（当前 1,812 对）。改判定线后直接重算，不需要重新扫描。

## 5. 卡片

### 5.1 收起时一行

```
∨ 第 N 组　● 状态　标签 · N 个文件　　　　　　　👁(划线)
```

| 关系 | 圆点 | 状态 | 标签 |
|---|---|---|---|
| 覆盖冲突 | 砖红 | 需查看 | 覆盖冲突 |
| 疑似同一 mod | 琥珀黄 | 可整理 | 疑似同一 mod |
| 合集重复 | 琥珀黄 | 可整理 | 合集重复 |

- 不写具体 package 名，只写文件数。
- 排序：红在前，黄在后；同色内按文件数降序。
- 「第 N 组」序号在一次扫描结果内固定，**筛选时不重排**（用于拖滚动条时定位）。

### 5.2 展开后

统一顺序：**一句话说明 → 文件列表 → 建议 → 右下角「技术详情」**。层级最多两层。

每个文件一行：文件名、所在文件夹、修改时间、大小，行尾 📁 在文件夹中显示、🗑 移到回收站（先确认）、👁 忽略。

**覆盖冲突**
- 说明：「这 N 个 mod 都在替换同一批东西（M 样<种类>），游戏只会用其中一份。」
- 文件行追加「撞 N 样 · 独有 M 样」。内容版本相同的文件归在一起，小字「以下 N 个内容相同」。
- 建议：独有为 0 的文件删除不会丢失其他内容；挑想要的那份保留。

**疑似同一 mod**
- 说明：「这几个文件大部分内容相同，像同一个 mod 装了几份。」有不同时追加「有 N 样不一样，疑似新旧版本」。
- 修改时间最新的文件标「最新」。
- 建议：保留最新的一份。

**合集重复**
- 说明：「<合集名> 里装着 N 个你另外单独放着的文件：X 个已被包含，Y 个存在不同。它还有 M 样只有合集里有。」
- 第一行是合集本身，标「合集」，追加「独有 M 样」。下面是被包含的文件，每行标「已被包含」或「存在不同」。
- 建议：「已被包含」的单独文件可以删除；删除合集会丢失 M 样。

### 5.3 技术详情

卡片上写「有多少」，技术详情写「具体是哪些」，给要用 Sims 4 Studio 修改的人看。

- 一张表，每行一个 TGI：编号（Type:Group:Instance 十六进制，可复制）· 种类名 · 每个文件里是第几版本（内容相同用同一版本号）。
- 疑似同一 mod：只列内容不同的 TGI，相同的折叠为一行「另有 N 样相同」。
- 合集重复：只列「存在不同」的文件差在哪些 TGI。
- 覆盖冲突：列出被抢的那一批。
- 种类名来自对照表；没有可靠来源的显示编号，不凭记忆填。
- 底部「复制详情」：整张表复制为纯文本。

## 6. 读取失败

不作为组。单独一块放在卡片列表最下面：

```
有 N 个文件没读成，以下结果不包括它们
文件名　　原因　　📁
```

原因用人话：文件损坏建议重新下载 / 格式暂不支持 / 单条资源过大 / 扫描期间文件被修改 / 无法访问。

点顶部「未完成」标签直接滚到这一块。

## 7. 筛选

- 顶部标签：全部 / 需查看 / 可整理 / 未完成，带数字。
- 漏斗弹窗：状态（需查看 / 可整理 / 未完成）、种类（覆盖冲突 / 疑似同一 mod / 合集重复 / 脚本）、「显示已忽略」（默认不勾）。筛选生效时漏斗显示小点。
- 脚本冲突沿用现有判定，按同样的红黄规则出卡。

## 8. 忽略

| 位置 | 作用范围 | 再次提醒的条件 |
|---|---|---|
| 组标题行的 👁 | 整组 | 组的文件集合或被抢 TGI 集合发生变化 |
| 文件行的 👁 | 只在这一组里去掉这个文件，其余文件重算；剩不到 2 个文件则组消失 | 同上 |

- 不提供「全局忽略某个文件」，避免它以后与真冲突相撞时被藏掉。
- 已忽略的组默认隐藏，底部灰字「已忽略 N 组」可点开；显示时标题旁灰色标签「已忽略」，图标变为睁眼，悬停提示「取消忽略」。
- 忽略记录存在本机设置里，键 = 组内文件相对路径集合 + 被抢 TGI 集合的指纹；存放位置待定。

## 9. 设置

| 设置项 | 默认 | 范围 | 说明文字 |
|---|---|---|---|
| 同一个 mod 的判定线 | 50% | 10%–100% | 两个文件中，共有资源占较大那个文件的比例达到此值，归为同一组 |

改动后立即重算，不重新扫描。设置写准确的数值和算法，不用「宽松/严格」这类模糊档位。

## 10. 不做

- 不改扫描、解压、内容比较逻辑。
- 不修改 package（不从文件中挖掉资源）。
- 不判断「哪个会生效」。
- 不做 XML 逐行对比（见 issue #11）。

## 11. 测试要求

- Core 分组逻辑写完整单元测试：包含判定、双向重合度、贪心不传递、判定顺序、独有数、忽略键变化。
- 界面测试覆盖展开、筛选、序号不重排、忽略、跳转、按钮命中、读取失败块存在；测试边界遵循 [AGENTS.md 的测试规则](../../AGENTS.md#10-完成标准)。

## 12. 待定

1. 覆盖冲突的圈卡规则（哪些文件放一张卡），需用真实数据试几种规则后定。
2. 合集包含的最小文件门槛：只有 1–2 样资源的小文件容易因碰巧共用一样原版资源被判为「已包含」。
3. NameMap 是否被游戏使用。
4. 忽略记录的存放位置。

## 数据依据（当前 Mods，2026-10-12）

| 统计 | 数值 |
|---|---|
| 撞号文件对（排除后） | 1,812 |
| 包含关系 → 合并后合集卡 | 595 → 67 |
| 疑似同一 mod 组（判定线 0.5 / 0.7 / 0.9） | 132 / 126 / 124，最大组 10 个文件 |
| 其余文件对 | 770，其中只撞 1 样的 479 |
| 卡片总数（其余按文件对计） | 969 |

撞得最多的资源是小编号的 CASPart / SimHotspotControl（例如 0x2AE9 在 16 个文件中有 13 个内容版本）。样本中带小编号捏人部件的文件均为改原版的 mod（Replacement / RemoveEALashes / Fixed），推测这一类主要是多个默认替换在抢同一个原版资源；软件判定不依赖编号大小。
