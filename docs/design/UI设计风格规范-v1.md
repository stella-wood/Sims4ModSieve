## 2. 整体气质

**克制、温暖、清楚，有工具感。**

页面用暖灰底、白色卡片和低饱和紫色构成层次。留白承担分区，细边框承担边界，标题和数据通过字体与字重区分。主要动作明确，辅助动作轻量。

沿用规则：

- 大面积背景保持暖色调；白色用于卡片内部。
- 紫色用于主要动作、当前导航和少量信息强调，不代表危险。
- 卡片与按钮以小圆角为主，不改成胶囊、大圆角或悬浮玻璃效果。
- 不引入大面积渐变、装饰阴影、无关插画或高饱和状态面板。
- 首页可以舒展；工作页优先承载文件信息，保持紧凑可扫读。
- 局部更改不自动升级为全局风格调整。

## 3. 页面结构与响应方式

新增或调整页面边距、内边距、控件间距及分区留白时，优先采用 4 DIP 的倍数，例如 4、8、12、16、20、24、28、32、52、88 DIP。需要光学对齐或适配紧凑内容时允许例外，以实际视觉效果为准。此规则用于后续布局修改，不据此批量调整既有已确认的间距。

### 3.1 外框与导航

| 项目 | 当前值 / 规则 |
|---|---|
| 默认窗口 | 1180×780 DIP |
| 最小窗口 | 920×640 DIP |
| 应用内导航高度 | 54 DIP，位于原生窗口标题栏下方 |
| 导航水平边距 | 28 DIP |
| 导航下边线 | 1 DIP，`BorderBrush` |
| 导航文字 | Microsoft YaHei UI，15，Normal |
| 当前导航 | 紫色文字；无填充胶囊、无大色块 |
| 右侧入口 | 设置，使用现有忙碌限制；当前页为紫色文字 |

首页、重复检测、冲突检测与设置共用这一条导航。页面切换不改变导航的高度、位置和字体。

### 3.2 首页

- 内容上边距 90、下边距 40。
- 水平布局比例为 `0.75* : 8* : 1.25*`，主内容占约 80%，并非严格居中，右侧留白更宽。
- 展示标题「让 Mod 文件夹清晰可控」使用 35 号等线 Bold。
- 副标题使用 16 号等线 SemiBold，暖灰色；上距 10，下距 34。
- 两张功能卡片等宽，间距 20；卡片内边距 20。
- 卡片高度为自身宽度的 `0.547`，最低 246。
- 卡片内部图标、说明、动作三个区域按 `0.32 : 0.49 : 0.19` 分配空间。
- 图标容器 46×46、圆角 6；功能标题 22，说明 14、行高 22。
- 2026-10-09 基线中的冲突卡片透明度为 0.62，标注「尚未开放」；当前入口已开放，卡片显示「进入检测」。
- 首页右下角仅在发现新版本时显示更新图标，点击打开 GitHub 发布页；启动检查与隐私规则见 [产品需求](../product/产品需求文档.md#7-联网与隐私)。

窗口变宽时，内容和卡片舒展；字体、图标和按钮字号不随整页同比放大。不要用整页 Viewbox 代替响应布局。

### 3.3 工作页

```text
┌──────────────── 顶部导航 ───────────────────┐
│ 返回            ┌──────── 结果标题与工具 ───┐│
│ ┌─ 范围卡片 ──┐ │                           ││
│ │ 范围 / 添加 │ │ 分组结果                   ││
│ │ 当前 Mods   │ │   展开资源 / 文件明细       ││
│ │ 来源列表    │ │                           ││
│ │             │ │ 结果区内部滚动             ││
│ │ 状态 / 进度 │ ├───────────────────────────┤│
│ │ 扫描 / 取消 │ │ 底部统计与操作             ││
│ └─────────────┘ └───────────────────────────┘│
└─────────────────────────────────────────────┘
```

- 外边距：左 28、上 18、右 28、下 28。
- 两列比例约 31:69，中间间距 16；左列最低宽度 300，因此窄窗口下不严格保持比例。重复检测与冲突检测的检查范围列共用最大宽度 346.67 DIP，对应 150% 显示缩放下约 520 像素；达到上限后新增宽度分配给结果区，窗口缩小时仍按原比例收窄。
- 「返回」位于左列上方，下方留出 24 DIP 行间距；左卡片顶部低于右卡片。这是当前布局事实，不应误改成强制齐顶。
- 左侧只管理范围、来源和扫描状态；右侧承载结果阅读及文件动作。
- 左卡片内边距 18；右卡片外层内边距 0，由各区域独立设定。
- 重复检测右侧标题区内边距 `20,17`，下边线 1；底栏内边距 `20,11,36,11`，上边线 1。冲突检测的标题与筛选栏尺寸在第 8 节规定。
- 来源列表与结果列表各自滚动。结果列表不显示水平滚动条，较长路径省略并提供 Tooltip。
- 全应用纵向滚动条共用细条外观：滑块视觉宽度 6 DIP、完整矩形命中宽度 12 DIP、圆角 2 DIP，默认滑块为 `#E8E5E1`，悬停滚动条或拖动滑块时为 `#C8C1B8`；轨道透明、无上下箭头，保留轨道翻页和滑块拖动操作。两页检查范围、结果列表、文件关系弹层，以及设置中的扫描计时、错误日志、许可证／声明文本框在内容溢出时常显。
- 首页、冲突功能总览和设置页外层使用同一纵向样式，滑块默认隐藏，保留透明命中区；整页滚动、鼠标进入滚动条或捕获拖动时显示，停止操作 1 秒后用 180 ms 淡出，悬停或拖动期间保持显示。内层内容滚动不触发外层滑块显示。技术详情横向滚动条保持独立样式和原有交互。
- 保留结果列表虚拟化与 Recycling；不要换成一次渲染全部大数据的长 StackPanel。

### 3.4 设置页

设置页的「常规」「删除与忽略」「诊断与反馈」「关于」及后续新增分类共用同一个内容区布局，外边距统一为左 88、上 52、右 88、下 50 DIP（WPF `Margin="88,52,88,50"`）。各分类沿用这组边距，不另设局部覆盖。内容随窗口宽度横向伸展，不设最大宽度限制；最大化时边距保持固定，字体和图标不随窗口缩放。分类内容与滚动条规格见 [设置页面方案](设置页面方案-v1.md)。

颜色的语义应保持稳定。新增页面优先复用资源；确需把已有局部色提取为资源时，保持视觉值不变。表中的局部值不代表当前已有同名全局 Token。

文字控件以变色强调鼠标悬停时，统一使用 `HoverTextBrush`，后续新增的同类效果也沿用。当前覆盖顶部导航、冲突页四个筛选标签和设置页两个「刷新」；已选中或键盘聚焦的控件，悬停时仍使用该色，移开后恢复其原有状态。此规则只统一已有文字悬停色，不为原本不变色的文字新增悬停效果，不改变常态、选中态、键盘焦点、图标、背景、边框或下划线的颜色。

淡紫色的「选择 / 更改」是辅助操作，不应被扩大成正文色、主要按钮色或错误提示色。不要因重用按钮模板而把它重新加粗或放大。

字号单位为 WPF DIP，不是印刷 pt。

| 角色 | 字体 / 字重 | 当前典型字号 |

| 品牌资源 | Bahnschrift SemiBold，回退 Microsoft YaHei UI / SemiBold | 由使用位置决定 |
| 首页展示标题 | 等线 / Bold | 35 |
| 首页功能卡标题 | Microsoft YaHei UI / SemiBold | 22 |
| 工作区标题 | Microsoft YaHei UI / SemiBold | 18 |
| 组标题 | Microsoft YaHei UI / SemiBold | 15 |
| 导航 | Microsoft YaHei UI / Normal | 15 |
| 首页副标题 / 说明 | 等线 / SemiBold | 16 / 14 |
| 数据、路径、统计 | Segoe UI Variable Text，回退等线 / Normal | 10–12，路径通常 11 |
| 文件名 | 重复检测沿用数据字体；冲突结果继承界面字体 / SemiBold | 重复检测继承控件字号；冲突结果显式为 12 |
| 结果组编号 | 继承界面字体 / SemiBold | 11 |
| 冲突页技术值 | 继承界面字体 / Normal | 10 |
| 当前 Mods 标题 | Microsoft YaHei UI / SemiBold | 12 |
| 「选择 / 更改」 | 继承界面字体 / Normal | 12 |
| 小标签 / 建议保留 | 当前字体 / SemiBold | 10 |
| 删除确认正文 | Microsoft YaHei UI / Normal | 14 |

`BodyTextStyle` 当前是等线 SemiBold，并不是 Normal；不要凭样式名字推断字重。部分按钮及文本沿用默认字号，后续显式提取字号时先核对渲染，避免隐性变大。

`BrandTextStyle` 与紫色晶锥 `BrandMarkImage` 已存在于资源中，但当前首页正文没有展示品牌字标。不要因资源存在，就自行新增一块品牌横幅。

层级靠字号、字重、颜色和位置共同建立。同一行不要让组编号、标题、路径、标签全部粗重；文件名高于路径，组标题高于文件名，统计弱于标题。

## 6. 组件规范

### 卡片与分隔

- `CardStyle`：白底、1 DIP 暖灰边框、圆角 4、默认内边距 20，无阴影。
- 展开文件区：暖灰底 `#F3F1ED`；当前是平直嵌套区域，不追加独立卡片边框。
- 来源行用细实线分隔；结果组用轻虚线分隔。两者不混用。
- 小标签圆角 3、内边距 `9,4`，浅紫底、紫色字；避免做成大型状态横幅。

### 按钮

后续新增或修改的按钮统一不显示边框，覆盖主次按钮、文字按钮、图标按钮及作为导航或切换入口的按钮。常态、悬停、按下、选中、禁用和键盘焦点状态均不绘制包围描边，也不显示系统虚线焦点框。WPF 模板不添加焦点边框，并将 `FocusVisualStyle` 设为 `{x:Null}`；保留控件的焦点能力、Tab 导航、键盘激活和完整矩形命中区域。需要状态反馈时使用文字、图标或底色变化，文字悬停色遵循第 4 节。

首页「进入检测」、两种检测的「添加／开始扫描／取消扫描」、重复检测的「清空勾选／一键勾选／删除所选」使用普通箭头光标，保留原有悬停效果。重复检测的批量展开／收起图标使用手形光标。顶部导航、冲突检测的筛选标签／漏斗／组展开箭头，以及删除确认窗「否／是」保留手形；其他控件的光标规则不变。

| 类型 | 当前样式 | 用法与尺寸 |
|---|---|---|
| 主动作 | `PrimaryButtonStyle` | 紫底白字，圆角 4，默认 Padding `18,10`，SemiBold |
| 次动作 | `SecondaryButtonStyle` | 暖灰底深字；「添加」「清空勾选」「取消扫描」「删除所选」 |
| 轻量操作 | `HeaderBackButtonStyle` | 无底色、灰字；「返回」及局部操作的基类 |
| 顶部导航 | `HeaderNavButtonStyle` | 透明底、Normal；悬停紫字 |
| 当前导航 | `ActiveHeaderNavButtonStyle` | 紫色文字 |
| 裸图标 | `BareIconButtonStyle` | 灰色图标，悬停紫色；矩形热区承担命中 |

局部规格：

- 添加 / 清空勾选 / 一键勾选：Padding `12,7`。
- 删除所选：Padding `16,8`，当前沿用次按钮；不要默认改成红色主按钮。
- 扫描：左卡片底部横向填满可用宽度；运行中同位置显示次按钮「取消扫描」。
- Mods 选择 / 更改：12 号、Normal、`#A892C5`，Padding `6,2`，与路径区垂直居中；不得恢复为大号粗体。
- 主按钮禁用透明度 0.45；导航禁用使用 MutedBrush 并叠加 0.45；裸图标禁用 0.4。不要擅自把这些不同控件全部统一成另一个数值。

### 来源与路径

- 来源行由复选框、名称和路径、移除按钮构成；内边距 `2,11`。
- 名称突出，路径弱化；完整路径保留在 Tooltip。
- 不可访问是独立运行时状态，用 10 号暖棕色文字表达。保留用户原来的勾选意图，不自动取消勾选。
- 来源移除按钮当前为「×」，18 号，Padding `7,2`。
- Mods 根目录卡片与扫描来源列表是两个语义不同的区域，不合并为同一个勾选项。

重复检测与冲突检测沿用相同的范围展示和操作规则，但分别维护文件夹列表与勾选状态。添加、移除、勾选只影响当前检测页；同一次应用运行期间切换页面或返回首页保留各自范围。完全关闭再打开时，两页都恢复默认范围：仅列出当前 Mods 文件夹并勾选；未设置且未发现默认 Mods 文件夹时，范围为空。上次添加的目录及勾选不持久化，旧设置中的来源列表也不恢复。

「当前 Mods 文件夹」位置仍共用并持久化。更改该位置会将目录添加或启用到当前检测页的范围，另一页现有范围不随之改变；下次启动时两页以该位置初始化。

### 重复检测结果组与文件行

- 组头包括展开箭头、组级复选框、组编号、主标题、弱化统计和可选范围标签。
- 主标题使用该组建议保留的文件名（含扩展名），旁边以灰色小字显示「N 份相同」；文件名过长时省略，Tooltip 显示完整文件名。
- 展开箭头单独占 20 DIP 列，图形约 10×6，线宽 1.8；箭头、组号、文件名、相同份数及下方大小说明的标题区域支持展开／收起，包含文字边缘留白。组复选框只改变选择；文件区和标题右侧其余空白不触发展开。
- 展开区外边距 `20,3,0,7`，内边距 `8,4`；文件行边距 `8,9`。
- 文件行使用复选框、文件名、完整路径、建议保留提示。建议保留项展示在组内前面，保留策略来自 Core。
- 「建议保留」用紫色文字标识，不以整行绿色背景强化。
- ListBox 自定义容器不显示系统整行蓝色选中底，操作选择由明确的复选框表达。

### 图标与命中区域

- 后续新增图标优先用轻量矢量 Path / DrawingImage，保持线条和视觉重量一致。
- 全部展开 / 收起为三条手风琴线，通过线距区分状态。图标 16×16、线宽 1.35、圆端点，按钮热区 24×24。
- 图标层不承担独立命中：内容 `IsHitTestVisible=false`，完整矩形宿主负责点击。
- 裸按钮宿主背景与表面同色，视觉无底色而热区完整。
- 首页「≡」「◇」、来源「×」和返回箭头是现存字符图标，不将其扩展成新增功能的通用图标体系。

### 删除确认与错误反馈

文件操作确认窗的尺寸和文案见[多选文件](冲突检测页面方案-v1.md#多选文件)。窗口不可调整大小、居中于父窗口、不单列任务栏入口；右侧依次为「否」「是」。后台仍执行文件复核；失败时另行说明。

意外错误目前使用系统 MessageBox；文件操作失败也用系统警告窗口，最多展示前 8 项并提示其余数量。这是现状，不应在文档中虚构成已实现的自定义 Toast 或统一紫色弹窗。

## 7. 文字与状态表达

应用内悬停提示（Tooltip）的默认首次显示延迟为 650 ms，由应用启动时统一设置，新增控件沿用该默认值。

用短语表达动作，用一行主状态加一行弱化细节表达过程。按钮通常不加句号；避免把页面标题、按钮动作和说明重复写三遍。技术标识放在详情中，不占据主要任务文案。

| 场景 | 当前行为 / 后续沿用要点 |
|---|---|
| 首次进入重复检测 | 展示来源，结果中央「尚未扫描」 |
| 开始扫描 | 新建结果会话、清除旧结果，来源编辑与主要文件操作锁定 |
| 扫描进行中 | 左底部进度、状态、取消；右侧空态同步当前扫描阶段；已知总量用确定进度，否则不确定进度 |
| 扫描完成有结果 | 右侧分组列表和底栏；左侧完成摘要及未完成分析数量 |
| 扫描完成无结果 | 左侧说明未发现重复；右侧空态同步「扫描完成，没有发现重复文件」 |
| 取消 / 失败 | 左侧状态与右侧空态分别显示「扫描已取消」「扫描没有完成」；不能包装成完整成功 |
| 来源离线 | 保留路径和勾选，显示「不可访问」；进入页面、开始扫描前刷新可用性 |
| 删除完成 / 部分失败 | 底部轻量提示；失败信息单独报告；有可撤回操作时显示「撤回」 |

已批准的结果会话联动：新增来源、移除部分来源、启停来源，保留旧结果；当前检测页全部来源移除，只清空该页结果、选择、状态与撤回记录；开始新扫描建立新会话。返回首页再进入不应自行清空结果。

重复检测的组级勾选继承既有规则：按建议删除集合选中，或手动选中整组全部文件，组复选框都可显示选中。不要在视觉重构中改变其业务语义。

重复检测组头不再显示「重点目录与其他位置重复」标签；「重点目录内部重复」「参照目录内部重复」仍保留，分组及排序规则不变。

路径可以省略显示，但两种检测的完整路径都必须包含文件名，并可通过 Tooltip 查看。不要把被截断的显示文本当作实际文件身份。

## 8. 冲突检测页面

四功能总览、页面返回与会话恢复规则见 [冲突检测页面方案](冲突检测页面方案-v1.md#页面范围)。四张功能卡均可进入对应页，只有基础排查已接入扫描，其余页显示「尚未开放」。字号与图标不随布局缩放。

评级与页面归属遵循 [冲突评级与拆分标准](../product/冲突评级与拆分标准.md)。当前 WPF 使用三种状态，绿色结果和新的分类边界尚待实现对齐。

### 8.1 标题与筛选横栏

右侧标题为「扫描结果」。横栏和漏斗共用筛选状态，点击单个状态只显示对应结果，「全部」恢复全部状态但保留类型选择。当前状态、类型、忽略开关及空筛选行为统一见 [分组方案的筛选规则](冲突检测分组方案-v2.md#7-筛选)。

| 项目 | 当前规则 |
|---|---|
| 标题与筛选文字间距 | 标题文字框底部至「全部」文字框顶部为 12 DIP |
| 标题 Margin | `20,16,20,3.48` |
| 横栏高度 / Margin | 32 DIP / 0 |
| 横栏内边距 | `38,0,20,0` |
| 横栏底线 | 1 DIP，`BorderBrush`，与重复检测一致 |
| 标签字号 / 点击高度 | 11 / 31 DIP |
| 状态圆点 | 10×10 DIP，沿用第 4 节现有状态资源 |
| 漏斗图形 / 点击区域 | 16×16 / 24×24 DIP，矩形宿主承担点击 |

横栏及标签无填充、无包围边框；文字悬停使用 `HoverTextBrush`。底部浅紫短横线在 150 ms 内渐显或淡出，选中线使用 `AccentBrush`，选中线覆盖悬停线。漏斗悬停、打开或键盘聚焦时变紫，点击与聚焦不绘制方框；有有效筛选时显示紫色小点。

### 8.2 漏斗筛选与扫描进度

漏斗弹层位于图标下方并向左展开，保持在应用窗口内。状态、种类和「显示已忽略」用细线分隔；使用既有列宽和间距，长种类名单独占一行，不撑宽列。筛选行为不再重复维护旧的「资源／脚本」二分类规则。

扫描期间禁用横栏与漏斗。阶段名称与进度数字的来源、未知总数、取消及迟到进度处理见 [扫描与会话](冲突检测页面方案-v1.md#扫描与会话)。

### 8.3 结果组与状态

卡片分类、标题、稳定编号、排序及展开点击区统一见 [分组方案的卡片规则](冲突检测分组方案-v2.md#5-卡片)，不再按单个 TGI 生成页面卡片。独立未完成文件和范围问题与卡片共用虚拟化列表。

卡片之间保留暖灰虚点线，工作页外层结果卡片沿用 `CardStyle`。不绘制状态大背景，也不恢复系统蓝色整行选中底。展开图形与矩形点击区分离，保留键盘操作，不绘制焦点方框。

### 8.4 文件行与技术详情

展开顺序为说明、文件列表、技术详情。文件行显示文件名、含文件名的完整路径、修改时间和大小；行尾图标、右键菜单与文件关系入口使用各自的命中区。文件操作沿用已实现的删除、禁用／启用和忽略服务。

文件注释、关系弹层、技术表格与列表模式、相关组跳转、吸附表头、横向虚拟化和复制详情统一见 [分组方案](冲突检测分组方案-v2.md)。技术行与文件行均为外层结果列表中的兄弟项，不恢复旧的嵌套长列表或内容版本子分组。

## 9. 局部调整边界

视觉附件保留各自日期的历史布局，不作为恢复已替换控件或旧文案的依据。相关页面以现行方案和代码核实现状；局部改动不自动授权整体改版。

## 10. 实现与验收清单

实现时优先复用 App.xaml 中的已有 Style。新增同类组件只增加必要差异；相似模板修改必须定位准确的 `x:Key`。

自动测试与人工视觉核验的边界遵循 [测试范围](../../AGENTS.md#10-测试范围) 和 [完成标准](../../AGENTS.md#11-完成标准)。本文的视觉数值用于实现与人工查看。

- 默认 1180×780、最小 920×640 均可用；长路径和多个标签不挤出主动作。
- 建议覆盖 100%、125%、150% DPI；窗口伸缩改变布局，不整体缩放文字。
- 检查初始、扫描中、取消、失败、完成有结果、完成无结果、部分无法比较等状态。
- 顶部导航、左底部扫描动作和右底部工具保持稳定；长列表在内容区滚动。
- 逐项验证 Tooltip、展开 / 收起、禁用态、键盘焦点与图标热区。
- 保留虚拟化；大量结果验收时同时检查滚动体验。
- 修改点击热区后运行 `BareIconButtonHitTests`；WPF 测试在 STA 环境执行。
- `Run.Text` 绑定只读 ViewModel 属性时显式使用 `Mode=OneWay`。
- UI 改动应构建通过、运行相关测试并实际启动检查；仅编译成功不等于可见效果验证完成。
- 不在界面事件里重写 Core 的判断规则，不通过新增状态布尔值绕开既有会话生命周期。
