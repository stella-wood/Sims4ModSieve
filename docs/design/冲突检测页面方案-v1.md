# 冲突检测页面方案 v1

状态：四入口总览与基础排查已接入 WPF，并完成临时样本扫描与窗口验证。其他三个板块显示「尚未开放」，真实分析流程未纳入本次接线。

[打开交互 demo](./prototypes/conflict-detection-demo.html)。用浏览器打开本地文件；数据与扫描进度均为示例，不读取或修改 Mods。颜色、尺寸、字体和通用组件沿用 [UI 设计风格规范](./UI设计风格规范-v1.md)。

## 页面范围

冲突检测先展示功能总览，参考现有首页，使用 2×2 卡片排列「基础排查」「报错日志分析」「健康性检查」「二分排查」四个入口。首页冲突卡片和顶部冲突导航均进入总览；点击功能卡后进入对应工作页，不使用四页签布局。工作页通过「返回冲突检测」回到总览，返回后保留当前结果。

功能卡沿用首页的白底、暖灰细边框、小圆角、矢量图标和标题层级。总览只介绍四种排查方式，不放扫描状态、结果筛选或技术标识。四个入口统一显示「进入排查→」，无边框、无底色，文字使用当前主按钮底色 `#6F5A91`（`AccentBrush`）；悬停和按下也不出现填充底色，保留键盘焦点提示与完整点击区域。此样式只用于这四个入口，不改变首页或其他按钮。其他三个功能在正式页面标注「尚未开放」，入口可查看对应状态页。

| 板块 | 本次原型 | 后续实现边界 |
|---|---|---|
| 基础排查 | 来源设置、扫描状态、资源和脚本结果、未完成分析 | 接入现有索引、资源比较与脚本扫描能力 |
| 报错日志分析 | 选择日志、分析、查看线索的流程草案 | 尚无分析服务，单独确定日志格式和归因规则 |
| 健康性检查 | 检查文件结构和读取问题的流程草案 | 可复用部分结构预检；检查范围需另行确定，不表示已完成完整健康检查 |
| 二分排查 | 准备、试运行、反馈与缩小范围的流程草案 | 尚无文件隔离和恢复流程，单独确定操作与恢复规则 |

HTML 原型的后三个工作页可以预览流程；正式 WPF 页面只显示对应标题与「尚未开放」，不执行真实分析、移动或禁用文件。

## 基础排查

左侧是「检查范围」卡片，沿用重复检测的当前 Mods、添加来源、来源勾选和移除操作。当前 Mods 路径与来源列表保留各自语义。扫描状态、进度和开始／取消按钮固定在左卡片底部。

右侧为「资源 / 脚本 / 未完成」。资源与脚本均按 Core 保留的文件对展示，两份文件名提供含文件名的完整路径 Tooltip。文件对身份使用完整 Windows 路径，不使用截断文字。结果没有选择删除、建议保留、可清理大小和撤回操作。

### 文件对与展开内容

资源层级为文件对 → 资源 → 内容分组 → 文件／技术明细；脚本层级为文件对 → 同名模块 → 内容分组 → 文件／技术明细。折叠时只投影父行，展开后才投影所需明细；所有层级都属于同一个平铺集合，通过缩进表达关系。

主状态与顺序使用 `ConflictPairPriority`：需查看 → 可整理 → 未完成。文件对和资源／模块行使用 Core 的逐对事实；原始 `Comparison`／`Collision` 只提供完整内容组上下文。三份以上文件参与时，同一内容组中的文件仍在一起展示，第三份文件的差异或失败不改变当前文件对状态。

需查看用局部色 `#A65F52`，可整理用 `#B18436`，未完成沿用 `#706C67`。圆点配文字，文字使用正文色，不铺状态背景。统计分别列需查看、可整理和未完成数量，主状态不覆盖未完成数量。混合文件对显示「疑似同一 mod 的两个版本」。

package 包含信息直接取 Core 的两个方向事实：单向显示「X 已被 Y 完全包含，删除 X 不会丢失内容」，双向显示「两份文件的资源完全一致」。脚本不显示整个归档包含信息。包含证据和展示资格见下方数据契约，不在 Desktop 重算。

资源差异解释为「这两个 mod 改了同一样东西，游戏只会用其中一个。」；脚本差异解释为「这两个 mod 带了同名脚本，游戏只会加载其中一份。」。不显示资源组编号，也不推断物品、功能或生效顺序。

### 技术详情

TGI、SHA256、技术错误码和原始错误详情只出现在默认收起的「技术详情」里，不进入普通展开。资源、内容分组、未完成条目和未完成文件各有自己的技术详情行；行本身只显示「技术详情」，Tooltip 留空或只给简短操作提示。先判断展开状态，再格式化对应技术值并生成平铺子行，不预先遍历所有文件拼接技术字符串。已展开的每个具体技术值行以 Tooltip 提供该行全文。

展开键在所属文件对、资源／模块／内容组身份之后追加技术详情段，所以不同父项的技术详情状态互不影响。未完成条目键还带同资源内的条目下标，同一资源的多个失败条目不共用状态。

未完成页的资源标识同样只在技术详情里出现：普通展开显示文件名、数量及中文类型／脚本条目名和人话原因明细，技术详情才给出「捏人部件 · TGI」及错误码、原始详情；脚本条目名可用于普通原因明细。资源类型取 `ResourceContentComparison.Key.Type`，不从错误文字推断。

### 筛选与空态

资源和脚本只有「全部 / 需查看 / 可整理」。全部显示 Core 保留的所有文件对；另两项分别匹配 `HasConfirmedDifference` 和 `HasConfirmedIdentical`，可重叠。筛选命中后保留全部子资源／模块，不再次筛选明细。空态数量按父级结果计算，不使用平铺行数。

底部「没查出冲突不代表没有冲突」仅在扫描完成，且整个会话的资源文件对、脚本文件对、未完成文件、范围问题全部为空时显示。筛选为空不触发；初始、扫描中、取消、失败不触发。

### 未完成

未完成文件与范围问题共用一个滚动列表。文件默认一行，显示文件名、未完成数量和主要原因；展开后先列普通原因明细，同时提供默认收起的技术详情；显式展开技术详情后保留路径、资源／模块、错误码与原始详情，整文件错误没有条目名时也保留原因。失败文件普通行显示各自文件名，Tooltip 给含文件名的完整路径。路径按 Windows 大小写规则合并；资源数量按不同失败 TGI 去重，脚本按原始条目名以 Ordinal 语义去重。合并 `Collisions.Uncompared` 和 `Issues`，保留未发生碰撞的失败条目。整个索引或归档未分析时数量未知，即使已知局部失败，也不将其冒充整文件数量。

原因按结构化 Code／Stage 归类，不解析 Message／Detail。主要原因按影响条目数排序，平局依次为：确认损坏、格式暂不支持、单条资源过大、扫描期间文件被修改、无法访问、文件过大、分析额度用尽、未知读取失败。通用未完成占位原因不参与具体原因竞争；技术详情保留全部原因和技术码。确认损坏的短语为「文件损坏，建议重新下载」。范围问题保留目录路径，不提供文件或资源数量。

### WPF 投影与虚拟化

`ConflictResultSession.Replace` 调用 Core 文件对汇总器，保存原始报告和共享的 Comparison／Collision 引用。`BuildVisibleRows` 接收视图、筛选、展开键快照和取消令牌，返回普通只读行数据，不创建 WPF 对象。展开键包含所属文件对及资源／模块／内容身份；Reset 清空报告、结果和展开状态。

扫描在后台完成汇总与初始投影后统一发布；后续筛选及展开投影也在后台执行，getter 只读取缓存。发布核对会话身份及递增请求号，重扫或清空来源替换会话身份并取消旧投影。展开集合只在 UI 调用路径修改，后台只读快照。异步投影任务处理取消和异常。

结果三个视图共用受限高度的 `ListBox`；来源使用独立的受限高度 `ListBox`。均使用 `VirtualizingStackPanel`、Recycling 和 `CanContentScroll`。展开行是集合中的兄弟项，不使用外层 ScrollViewer、嵌套长 ItemsControl 或承载所有子项的父项 StackPanel。展开图形为 16×16 矢量，24×24 透明矩形宿主负责命中，按钮支持键盘操作并显示焦点边框。展开按钮无障碍名称为「展开／收起 + 玩家标题」，结果行无障碍名称只给玩家标题；稳定展开键仅用于 AutomationId。实际文件展开明细使用第五层缩进 80。

默认窗口测试共用测试专用 `WpfTestHost` 的唯一 Application 和存活 STA Dispatcher；分别打开和关闭窗口。窗口显式加载 `Assets/Sims4ModSieve.ico` 作为标题栏图标，测试项目只以链接内容项复制该现有 ICO。虚拟化测试统计实际容器、文本及所有元素，并验证滚到远处再返回的内容和展开状态。

### 扫描与会话

正式扫描依次读取 package 索引、比较候选资源内容、扫描脚本模块。三个阶段共用来源快照和取消令牌。玩家进度按阶段映射为查找资源、读取资源索引、比较资源、查找脚本、比较同名脚本、整理文件对，不直接展示 Core 的完成摘要。

`ConflictStatus` 只显示中文阶段名称；`ConflictPhase` 在扫描期间显示该阶段真实的「完成数 / 总数」，数字取自结构化进度参数（`CompletedItems`／`TotalItems`、`CompletedResources`／`TotalResources`），不解析 Core 的 Message。总数未知或为零时清空数字，只留阶段名称，并把 `ConflictIndeterminate` 置为真；`ProgressBar.Maximum` 用独立的 `ConflictProgressMaximum`，未知时固定为 1，不冒充真实总数。进入新阶段、取消、失败、清空来源和重扫都清掉上一阶段的数字并恢复不确定态。阶段切换、取消和迟到进度仍按 generation 与当前阶段校验，旧任务的进度不能写回新会话。

三个底层入口取消时均抛出 `OperationCanceledException`，不返回该阶段的部分报告；当前界面在全部阶段完成并整理后统一发布结果，取消或失败不保留部分报告。扫描完成后继续使用现有的未完成文件数／范围问题数摘要。

会话联动沿用 [Agent 指南的结果会话规则](../../AGENTS.md#73-结果会话)。两种检测共享来源配置，结果各自保存；不另建一份容易失去同步的来源设置。清空来源同时重置关联结果，开始新扫描替换对应检测会话，旧任务的迟到进度不能写回新会话。

| 阶段 | 结果区文案和行为 |
|---|---|
| 初始 | 尚未扫描 |
| 扫描中 | 显示当前阶段，可取消，锁定来源编辑 |
| 已取消 | 扫描已取消，不显示完整成功结论 |
| 完成有结果 | 分组结果及未完成分析入口 |
| 完成无结果 | 已分析范围未发现冲突；仍展示未完成项 |
| 失败 | 扫描没有完成，显示安全摘要，允许重试 |

原型提供独立的演示状态选择器。该选择器和示例标记不进入正式产品。

## 文件对汇总数据契约

文件对汇总数据层已接入基础排查结果页。Desktop 直接消费以下契约。

`PackageConflictScanReport.ResourceInventories` 为只读清单，默认空集合，保留报告原有的位置参数构造方式。每个 `PackageResourceInventory` 保存发现阶段的规范 `Path`、完整索引读取时的 `ScannedStamp` 和全部索引项的 `ResourceCount`，包含未撞号资源。索引失败的 package 不进入清单；清单不保存完整索引，也不追加文件读取。

`ConflictPairSummaryBuilder` 提供两个同步方法，均接收取消令牌并返回只读列表：

- `BuildPackagePairs(PackageConflictScanReport, ResourceContentComparisonReport, CancellationToken)` 返回 `PackageConflictPairSummary`。
- `BuildScriptPairs(ScriptModuleScanReport, CancellationToken)` 返回 `ScriptConflictPairSummary`。

两类汇总均保存 `FirstPath`、`SecondPath`、差异／一致／未完成数量及对应的独立事实 `HasConfirmedDifference`、`HasConfirmedIdentical`、`HasIncomplete`；同时有一致与差异时，`IsSuspectedModVersionPair` 为真。package 使用 `DifferentResourceCount`、`IdenticalResourceCount`、`IncompleteResourceCount` 和 `Resources`；脚本使用 `DifferentModuleCount`、`IdenticalModuleCount`、`IncompleteModuleCount` 和 `Modules`。package 另有两个独立方向的 `FirstContainedInSecond`、`SecondContainedInFirst`。

`PackagePairResourceMatch.Comparison`、`ScriptPairModuleMatch.Collision` 引用原始记录，保留完整 `ContentGroups` 与 `Uncompared`，不为每个文件对复制内容组和来源列表。明细上的三个事实只描述所属文件对，不能用原始记录的全组 `Verdict` 替代它们。

### 配对与展示资格

路径按 `PathRules.Comparer` 去重，两端按路径稳定排序，不生成自身配对。相同路径的大小写拼写以 Ordinal 最小的拼写稳定表示。跨多个 TGI 或顶层脚本包仍合并为同一个无方向文件对。数量分别按不同 TGI 和大小写敏感的模块名（`StringComparer.Ordinal`）计数，不按 occurrence 累加。

每条重叠只对共同出现的两份文件判定：成功且在同一内容组为一致，成功且在不同组为差异，其中任一文件失败为未完成。第三份文件的差异或失败不传给这两份文件。差异、一致与未完成分别保留，失败不覆盖已经确认的事实。

有差异、有未完成，或已证明至少一个方向的 package 完全包含时保留文件对；仅有一致的局部重叠隐藏。脚本本阶段不证明整个归档包含，只有一致碰撞的文件对隐藏。

汇总和明细的 `Priority` 使用 `ConflictPairPriority`：有差异为 `NeedsReview`（需查看），否则有一致为 `CanOrganize`（可整理），否则为 `Incomplete`（未完成）。未完成数量独立保留。文件对先按此顺序，再按两端路径排序；明细先按此顺序，再按数值 TGI 或 Ordinal 模块名排序。该枚举只表达展示顺序，不改变现有 Verdict。

### package 完全包含的证明

对 X–Y 两个方向分别证明。只有 X 的全部资源数大于零，且 X–Y 已确认一致的不同 TGI 数恰好等于 X 的 `ResourceCount`，才可能认定 X 完全被 Y 包含。完整索引总数包含 X 的独有资源，因此仅有撞号资源一致不能通过该证明；多个其他文件合起来覆盖 X 也不能算作某个单一 Y 包含 X。依据是现有 `LlamaLogicPackageIndexReader` 拒绝重复 TGI，每个索引项对应一个不同资源键。

证明还要求两端均有清单和对应的 `ResourceContentComparisonReport.Packages` 稳定版本：清单戳、版本的 `ScannedStamp`、`StampAfterRead` 及该文件对成功资源 occurrence 的 `PackageStamp` 必须一致。缺少证据、版本不稳定或该对有差异／未完成时不证明包含；第三份文件失败不影响证据完整的 X–Y。双方全部资源一致时，两个方向都可以成立。所有核对只使用已有报告，不重新读取或哈希文件；结论针对报告中的已读取版本，不宣称文件此后仍未变化。

构建器先从不同内容组和失败参与文件收集候选文件对。package 另按文件统计有稳定版本证据的不同重叠资源键；不足完整索引总数的文件不展开一致配对，其余按所需 TGI 求内容一致且版本稳定的对端交集。先处理参与文件较少的 TGI，只保留当前交集，交集为空立即停止，不为所有对端累计资源键集合。同一 TGI 的重复记录先按对端并集处理，不重复计数；交集中可保留多个完整覆盖的对端。随后遍历全部比较记录，只为候选补齐明细并执行最终判定，因此后出现的差异或失败仍能保留之前的一致明细，纯一致的局部重叠不分配配对和逐条明细。展开内容继续引用原始记录。

构建器在报告遍历、候选配对内循环、排序和结果构建中检查取消，取消抛出 `OperationCanceledException`，不发布部分汇总。确需展示的大量文件对仍可能有组合规模。该层不推断生效文件、加载顺序或删除建议。
