# 冲突检测页面方案 v1

状态：四入口总览与基础排查已接入 WPF；结果区按资源／脚本模块展示默认收起的卡片，独立未完成项与范围问题合并展示。其他三个板块显示「尚未开放」，尚未接入真实分析流程。

[打开交互 demo](./prototypes/conflict-detection-demo.html)。原型保留早期入口和流程，结果布局以本方案及 WPF 为准；数据与扫描进度均为示例，不读取或修改 Mods。颜色、尺寸、字体和通用组件沿用 [UI 设计风格规范](./UI设计风格规范-v1.md)。

## 页面范围

冲突检测首次进入时展示功能总览，参考现有首页，使用 2×2 卡片排列「基础排查」「报错日志分析」「健康性检查」「二分排查」四个入口。点击功能卡后进入对应工作页，不使用四页签布局。同次运行期间通过首页冲突卡片或顶部冲突导航再次进入时，恢复上次的总览或工作页；工作页通过「返回冲突检测」回到总览，返回后保留当前结果。页面位置不持久化，重新启动后首次进入显示总览。

功能卡沿用首页的白底、暖灰细边框、小圆角、矢量图标和标题层级。总览只介绍四种排查方式，不放扫描状态、结果筛选或技术标识。四个入口统一显示「进入排查→」，无边框、无底色，文字使用当前主按钮底色 `#6F5A91`（`AccentBrush`）；悬停和按下也不出现填充底色，保留键盘焦点提示与完整点击区域。此样式只用于这四个入口，不改变首页或其他按钮。其他三个功能在正式页面标注「尚未开放」，入口可查看对应状态页。

| 板块 | 当前 WPF | 后续实现边界 |
|---|---|---|
| 基础排查 | 来源、扫描与取消、资源／模块卡片、复选筛选、显式技术详情 | package 包含尚未接入重复检测 |
| 报错日志分析 | 尚未开放状态页 | 尚无分析服务，单独确定日志格式和归因规则 |
| 健康性检查 | 尚未开放状态页 | 可复用部分结构预检；完整检查范围另行确定 |
| 二分排查 | 尚未开放状态页 | 尚无文件隔离和恢复流程，单独确定操作与恢复规则 |

HTML 原型的后三个工作页可以预览流程；正式 WPF 页面只显示对应标题与「尚未开放」，不执行真实分析、移动或禁用文件。

## 基础排查

左侧是「检查范围」卡片，沿用重复检测的当前 Mods、添加来源、来源勾选和移除操作。当前 Mods 路径与来源列表保留各自语义。扫描状态、进度和开始／取消按钮固定在左卡片底部。

右侧为「扫描结果」。资源、脚本模块、独立未完成文件和范围问题共用一个滚动列表。结果没有选择删除、禁用、建议保留、可清理大小和撤回操作。「扫描完成」只在左侧状态区出现。

### 卡片与展开内容

Core 文件对汇总仍负责资源与模块的展示资格及比较事实。Desktop 按 TGI／大小写敏感模块名合并这些文件对明细，每个资源或模块只有一组结果，保留原始 Comparison／Collision 的完整内容组上下文。同一种资源类型的不同 TGI 不合并。

所有结果组默认收起，组本身无边框，组间沿用重复检测的暖灰虚点线（`#D8D3CC`、`2,4`、透明度 0.78）。组标题行之间的分隔区域为 20 DIP：虚线上距 10、线高 1、下距 1、下一组上距 8。标题行从左到右为展开箭头、10 DIP 状态圆点、紫色「第 N 组」与资源中文类型／模块名，状态文字保留在右侧。编号按完整扫描结果的排序从 1 分配，状态或类型筛选后保留原编号，不重排，不作为展开身份。卡片主状态取参与明细中最高优先级的 `ConflictPairPriority`，顺序为需查看 → 可整理 → 未完成；不修改 Core 的逐对结论。

需查看用局部色 `#D33C2E`，可整理用 `#D99316`，未完成用 `#948C84`。结果组的状态只在标题行显示一次，圆点配文字，文字使用正文色，不铺状态背景。

展开后直接列文件名、所在文件夹、扫描时的修改时间与文件大小，每个文件在同一卡片中只显示一次，文件路径按 Windows 大小写规则去重。没有扫描文件戳时显示时间／大小未知，不为展示重新读取文件。文件名及文件夹 Tooltip 保留含文件名的完整路径。

只有两个文件时不显示内容分组。三个及以上文件且存在多种已确认内容时，相同内容的文件连续展示，用小字「以下 N 个内容相同」标记多文件内容组；标记不可折叠，也不给单个文件标记相同内容。失败文件保留在文件列表中，用文字说明失败原因。

文件列表之后显示一句原因。资源差异为「这几个 mod 改了同一样东西，游戏只会用其中一个」；脚本差异为「这几个 mod 带了同名脚本，游戏只会加载其中一份」。一致项只描述该项资源／模块内容相同，未完成项说明无法确认全部内容。不显示技术资源编号、文件对统计、package 删除建议或具体生效文件。

### 技术详情

每张卡片只有一个右侧轻量「技术详情」入口，默认收起。点击后才格式化并投影 TGI、SHA256、含文件名的完整路径、解压大小、技术错误码和原始错误详情。技术值行提供全文 Tooltip，与普通文件行使用相同缩进，不继续嵌套文件折叠。

展开键使用资源 TGI／模块名／未完成文件路径身份，技术详情键在所属卡片键后追加固定段。筛选切换不会丢失展开状态；不同卡片及其技术详情状态互不影响。

### 筛选与空态

漏斗图标位于「全部」筛选横栏最右侧。漏斗点击及聚焦不绘制方框，键盘焦点通过图标变紫表达。点击弹出状态与类型两类复选项，各自提供「全部」，其余为「需查看、可整理、未完成」和「资源、脚本」。每类用三列布局，行数按项目数量自动增长；两类之间用细线分隔。「全部」勾选／取消会全选／清空所属类别，部分选择时该类「全部」不勾选，默认两类均全选；同一类别内取并集，状态与类型之间取交集，可以全部取消。状态匹配卡片主状态，命中后保留卡片的全部文件和失败上下文。资源筛选包含 package 未完成项，脚本筛选包含 script 未完成项；范围问题按来源扫描阶段归入对应类型。

标题与筛选文字框之间约 12 DIP；标题下方为 32 DIP 高的无底色横栏，只有底部一条浅黑分隔线，最前面提供无圆点的「全部」，相对「扫描结果」标题右移 18 DIP，约对齐「描」字，后接「需查看、可整理、未完成」三个圆点标签。「全部」恢复全部状态，悬停时文字变为深紫（`#624D89`），不显示短横线，不保留选中态，默认展示全部。三个状态标签悬停时文字变紫，短横线使用浅紫（`#A892C5`），进入与离开各用 150 ms 渐显／淡出；三个状态标签选中时仍使用导航紫色 `AccentBrush`（`#6F5A91`），选中线覆盖悬停线，圆点保持状态色。点击标签只展示对应主状态，再次点击已选中的标签仍保持选中，点击「全部」恢复全部状态；悬停效果始终正常显示；横栏操作始终保留漏斗中的资源／脚本类型选择；漏斗继续支持组合筛选，与横栏共享同一筛选状态，组合或全部显示时横栏不选中单个标签。类型筛选仍由漏斗控制。扫描期间禁用横栏。

任一复选项取消后，漏斗显示小点。全部恢复后小点消失。筛选状态沿用会话生命周期：返回首页、部分来源调整保留；清空来源或开始新扫描恢复全选。筛选为空显示「没有符合筛选条件的结果」，不改变全会话的扫描结论。

底部「没查出冲突不代表没有冲突」仅在扫描完成，且整个会话的资源文件对、脚本文件对、未完成文件、范围问题全部为空时显示。筛选为空不触发；初始、扫描中、取消、失败不触发。

### 未完成

已在资源／模块卡片中显示的失败条目不再复制为独立文件卡；按路径、条目标识和错误码核对，其他未碰撞失败仍保留。未完成文件标题只显示文件名和状态，展开后列文件信息及人话原因，再提供统一技术详情。范围问题显示独立卡片，展开后给原因与技术详情，不伪造文件信息。

会话底层仍汇总 `Collisions.Uncompared` 和 `Issues`。路径按 Windows 大小写规则合并；资源数量按不同失败 TGI 去重，脚本按原始条目名以 Ordinal 语义去重。整个索引或归档未分析时数量未知，即使已知局部失败，也不将其冒充整文件数量。

原因按结构化 Code／Stage 归类，不解析 Message／Detail。主要原因按影响条目数排序，平局依次为：确认损坏、格式暂不支持、单条资源过大、扫描期间文件被修改、无法访问、文件过大、分析额度用尽、未知读取失败。通用未完成占位原因不参与具体原因竞争；技术详情保留全部原因和技术码。确认损坏的短语为「文件损坏，建议重新下载」。

### WPF 投影与虚拟化

`ConflictResultSession.Replace` 调用 Core 文件对汇总器，保存原始报告和共享的 Comparison／Collision 引用。`BuildVisibleRows` 接收类型视图、状态筛选、展开键快照和取消令牌，返回普通只读行数据，不创建 WPF 对象。Reset 清空报告、结果和展开状态。

扫描在后台完成汇总与初始投影后统一发布；后续筛选及展开投影也在后台执行，getter 只读取缓存。发布核对会话身份及递增请求号，重扫或清空来源替换会话身份并取消旧投影。展开集合只在 UI 调用路径修改，后台只读快照。异步投影任务处理取消和异常。

全部结果共用受限高度的 `ListBox`；来源使用独立的受限高度 `ListBox`。均使用 `VirtualizingStackPanel`、Recycling 和 `CanContentScroll`。展开行是集合中的兄弟项，不使用外层 ScrollViewer、嵌套长 ItemsControl 或承载所有子项的父项 StackPanel。展开图形为 16×16 矢量，24×24 透明矩形宿主负责命中，按钮支持键盘操作，沿用重复检测展开箭头的无焦点方框展示，点击或聚焦后不绘制方框。展开按钮无障碍名称为「展开／收起 + 玩家标题」，结果行无障碍名称只给玩家标题；稳定展开键仅用于 AutomationId。结果组由相邻的标题／文件／原因／技术行组成，末行绘制虚点分隔线；所有子行只有一级缩进。漏斗同样使用 16×16 矢量与 24×24 矩形热区。

默认窗口测试共用测试专用 `WpfTestHost` 的唯一 Application 和存活 STA Dispatcher；分别打开和关闭窗口。窗口显式加载 `Assets/Sims4ModSieve.ico` 作为标题栏图标，测试项目只以链接内容项复制该现有 ICO。虚拟化测试统计实际容器、文本及所有元素，并验证滚到远处再返回的内容和展开状态。

### 扫描与会话

正式扫描依次读取 package 索引、比较候选资源内容、扫描脚本模块。三个阶段共用来源快照和取消令牌。玩家进度按阶段映射为查找资源、读取资源索引、比较资源、查找脚本、比较同名脚本、整理文件对，不直接展示 Core 的完成摘要。

`ConflictStatus` 显示中文阶段名称；`ConflictProgressText` 显示该阶段真实的「完成数 / 总数」，数字取自结构化进度参数（`CompletedItems`／`TotalItems`、`CompletedResources`／`TotalResources`），不解析 Core 的 Message。总数未知或为零时清空数字，只留阶段名称，并把 `ConflictIndeterminate` 置为真；`ProgressBar.Maximum` 用独立的 `ConflictProgressMaximum`，未知时固定为 1，不冒充真实总数。进入新阶段、取消、失败、清空来源和重扫都清掉上一阶段的数字并恢复不确定态。阶段切换、取消和迟到进度仍按 generation 与当前阶段校验，旧任务的进度不能写回新会话。`ConflictPhase` 用于完成后的未完成文件／范围问题摘要及取消、失败提示，不承载进度数字。

三个底层入口取消时均抛出 `OperationCanceledException`，不返回该阶段的部分报告；当前界面在全部阶段完成并整理后统一发布结果，取消或失败不保留部分报告。扫描完成后继续使用现有的未完成文件数／范围问题数摘要。

会话联动沿用 [Agent 指南的结果会话规则](../../AGENTS.md#73-结果会话)。两种检测分别维护来源列表、勾选状态及结果。新增、移除、勾选仅影响当前检测的范围；清空范围只重置对应检测的结果。当前应用运行期间切换页面保留各自范围与会话，关闭再打开时均恢复默认勾选当前 Mods 文件夹，不恢复上次来源或勾选；未设置且未发现默认目录时范围为空。「当前 Mods 文件夹」位置仍共用并持久化，更改位置只向当前检测范围添加或启用该目录。开始新扫描替换对应检测会话，旧任务的迟到进度不能写回新会话。

| 阶段 | 结果区文案和行为 |
|---|---|
| 初始 | 尚未扫描 |
| 扫描中 | 显示当前阶段，可取消，锁定来源编辑 |
| 已取消 | 扫描已取消，不显示完整成功结论 |
| 完成有结果 | 资源／模块及独立未完成卡片 |
| 完成无结果 | 已分析范围未发现冲突；仍展示未完成项 |
| 失败 | 扫描没有完成，显示安全摘要，允许重试 |

原型提供独立的演示状态选择器。该选择器和示例标记不进入正式产品。

## 文件对汇总数据契约

文件对汇总数据层已接入基础排查结果页。Desktop 直接消费以下契约。

`PackageConflictScanReport.ResourceInventories` 为只读清单，默认空集合，保留报告原有的位置参数构造方式。每个 `PackageResourceInventory` 保存发现阶段的规范 `Path`、完整索引读取时的 `ScannedStamp`、全部索引项的 `ResourceCount` 和只读 `ResourceTypeCounts`，类型计数包含未撞号资源；旧构造不提供类型计数时该字段为 null，旧文件对入口不依赖它。索引失败的 package 不进入清单；清单不保存完整索引，也不追加文件读取。

`ConflictPairSummaryBuilder` 提供两个同步方法，均接收取消令牌并返回只读列表：

- `BuildPackagePairs(PackageConflictScanReport, ResourceContentComparisonReport, CancellationToken)` 返回 `PackageConflictPairSummary`。
- `BuildScriptPairs(ScriptModuleScanReport, CancellationToken)` 返回 `ScriptConflictPairSummary`。

两类汇总均保存 `FirstPath`、`SecondPath`、差异／一致／未完成数量及对应的独立事实 `HasConfirmedDifference`、`HasConfirmedIdentical`、`HasIncomplete`；同时有一致与差异时，`IsSuspectedModVersionPair` 为真。package 使用 `DifferentResourceCount`、`IdenticalResourceCount`、`IncompleteResourceCount` 和 `Resources`；脚本使用 `DifferentModuleCount`、`IdenticalModuleCount`、`IncompleteModuleCount` 和 `Modules`。package 另有两个独立方向的 `FirstContainedInSecond`、`SecondContainedInFirst`。

`PackagePairResourceMatch.Comparison`、`ScriptPairModuleMatch.Collision` 引用原始记录，保留完整 `ContentGroups` 与 `Uncompared`，不为每个文件对复制内容组和来源列表。明细上的三个事实只描述所属文件对，不能用原始记录的全组 `Verdict` 替代它们。

### 配对与展示资格

路径按 `PathRules.Comparer` 去重，两端按路径稳定排序，不生成自身配对。相同路径的大小写拼写以 Ordinal 最小的拼写稳定表示。跨多个 TGI 或顶层脚本包仍合并为同一个无方向文件对。数量分别按不同 TGI 和大小写敏感的模块名（`StringComparer.Ordinal`）计数，不按 occurrence 累加。

每条重叠只对共同出现的两份文件判定：成功且在同一内容组为一致，成功且在不同组为差异，其中任一文件失败为未完成。第三份文件的差异或失败不传给这两份文件。差异、一致与未完成分别保留，失败不覆盖已经确认的事实。

有差异、有未完成，或已证明至少一个方向的 package 完全包含时保留文件对；仅有一致的局部重叠隐藏。脚本本阶段不证明整个归档包含，只有一致碰撞的文件对隐藏。

汇总和明细的 `Priority` 使用 `ConflictPairPriority`：有差异为 `NeedsReview`（需查看），否则有一致为 `CanOrganize`（可整理），否则为 `Incomplete`（未完成）。未完成数量独立保留。文件对先按此顺序，再按两端路径排序；明细先按此顺序，再按数值 TGI 或 Ordinal 模块名排序。该枚举只表达展示顺序，不改变现有 Verdict。

### package 完全包含的证明

对 X–Y 两个方向分别证明。只有 X 的全部资源数大于零，且 X–Y 已确认一致的不同 TGI 数恰好等于 X 的 `ResourceCount`，才可能认定 X 完全被 Y 包含。完整索引总数包含 X 的独有资源，因此仅有撞号资源一致不能通过该证明；多个其他文件合起来覆盖 X 也不能算作某个单一 Y 包含 X。依据是现有 `LlamaLogicPackageIndexReader` 拒绝重复 TGI，每个索引项对应一个不同资源键。

证明还要求两端均有清单和对应的 `ResourceContentComparisonReport.Packages` 稳定版本：清单戳、版本的 `ScannedStamp`、`StampAfterRead` 及该文件对成功资源 occurrence 的 `PackageStamp` 必须一致。缺少证据、版本不稳定或该对有差异／未完成时不证明包含；第三份文件失败不影响证据完整的 X–Y。双方全部资源一致时，两个方向都可以成立。所有核对只使用已有报告，不重新读取或哈希文件；结论针对报告中的已读取版本，不宣称文件此后仍未变化。

构建器先从不同内容组和失败参与文件收集候选文件对。package 另按文件统计有稳定版本证据的不同重叠资源键；不足完整索引总数的文件不展开一致配对，其余按所需 TGI 求内容一致且版本稳定的对端交集。先处理参与文件较少的 TGI，只保留当前交集，交集为空立即停止，不为所有对端累计资源键集合。同一 TGI 的重复记录先按对端并集处理，不重复计数；交集中可保留多个完整覆盖的对端。随后遍历全部比较记录，只为候选补齐明细并执行最终判定，因此后出现的差异或失败仍能保留之前的一致明细，纯一致的局部重叠不分配配对和逐条明细。展开内容继续引用原始记录。

构建器在报告遍历、候选配对内循环、排序和结果构建中检查取消，取消抛出 `OperationCanceledException`，不发布部分汇总。确需展示的大量文件对仍可能有组合规模。该层不推断生效文件、加载顺序或删除建议。

### v2 Core 分组入口

`ConflictPairSummaryBuilder.BuildGroupingPackagePairs` 先过滤排除类型和退出文件，展开全部剩余撞号文件对，包括旧入口隐藏的纯一致局部重叠。继续使用 `PackagePairResourceMatch` 的逐对事实与共享原始 Comparison；不使用旧包含证明字段替代 v2 集合关系。`BuildPackagePairs` 和 `BuildScriptPairs` 的展示资格、包含证明及排序保持原契约。

`PackageConflictGroupingBuilder.Prepare` 接收原始索引与内容报告，返回只读 `PackageConflictGroupingInput`：排除后的文件总数与资源数、文件戳、文件对、共享比较引用，以及退出文件的原始扫描问题、失败资源、无效版本和输入缺数据原因。新入口需要完整类型数量，旧报告缺失时明确报告输入缺数据；成功索引的清单数量不齐则直接拒绝 Prepare，不补读文件。`Build` 仅接收准备好的输入与参数，生成文件对关系、卡片成员、相关 TGI、各成员计数及合集内容事实；取消不发布部分结果。

排除、四种关系、计数、参数和忽略键的规则统一见[分组方案 v2](冲突检测分组方案-v2.md)。当前 `ConflictResultSession` 仍消费旧投影，WPF 尚未接入新分组入口。
