## 页面范围

冲突检测首次进入时展示功能总览，参考现有首页，使用 2×2 卡片排列「基础排查」「报错日志分析」「健康性检查」「二分排查」四个入口。点击功能卡后进入对应工作页，不使用四页签布局。同次运行期间通过首页冲突卡片或顶部冲突导航再次进入时，恢复上次的总览或工作页；工作页通过「返回冲突检测」回到总览，返回后保留当前结果。页面位置不持久化，重新启动后首次进入显示总览。

功能卡使用白底、无边框、小圆角、矢量图标和标题层级；首页卡片样式不变。总览标题为「Mod 冲突检测」，不显示副标题；标题与四卡沿用首页按宽度伸展的方式：普通窗口使用 `0.75* : 8* : 1.25*` 水平分区，主内容占可用宽度的 80%；仅宿主窗口最大化时改用 `0.75* : 6.9* : 2.35*`，主内容约占 69%，还原后恢复普通窗口布局。两种状态左侧留白均为 7.5%，标题左边与卡片左边对齐。标题固定在滚动区外，短窗口仅四卡区域滚动。四卡保持 2×2 等宽等高，横纵间距均为 20 DIP；单卡高度随宽度按 `0.547` 比例调整，最低 200 DIP，不按窗口高度限制横向伸展。卡片内边距为 20 DIP，图标、标题说明、动作按首页的 `0.32* : 0.49* : 0.19*` 分区分配空间，文字和图标保持原尺寸。总览只介绍四种排查方式，不放扫描状态、结果筛选或技术标识。四个入口统一显示「进入排查→」，无边框、无底色，文字使用当前主按钮底色 `#6F5A91`（`AccentBrush`）；悬停和按下也不出现填充底色，保留键盘焦点提示与完整点击区域。此样式只用于这四个入口，不改变首页或其他按钮。其他三个功能在正式页面标注「尚未开放」，入口可查看对应状态页。

## 基础排查

左侧是「检查范围」卡片，沿用重复检测的当前 Mods、添加来源、来源勾选和移除操作。当前 Mods 路径与来源列表保留各自语义。扫描状态、进度和开始／取消按钮固定在左卡片底部。

右侧为「扫描结果」。v2 文件组、重复文件、脚本模块、独立未完成文件和范围问题共用一个滚动列表。文件行提供打开文件夹、本组忽略和回收站删除；结果区底栏复用重复检测的批量展开／收起、删除结果提示与撤回入口；不显示右侧容量汇总或批量删除，不增加批量选择。批量展开／收起只作用于当前筛选可见且可展开的卡，保留隐藏卡及技术详情自身的展开状态，与重复检测互不影响；位置保持规则见[分组方案 v2](冲突检测分组方案-v2.md#7-筛选)。撤回沿用当前冲突会话的最近删除记录，清空来源或开始新扫描后重置。「扫描完成」只在左侧状态区出现。

### 文件组、关系与文件操作

卡片分类、计数、排序、稳定身份与编号，以及文件行、技术表格、关系弹层、忽略、重复页导航和删除撤回规则统一见[分组方案 v2](冲突检测分组方案-v2.md#5-卡片)。现有检查范围、扫描区、筛选横栏位置和其他页面布局保留。漏斗只增加文件组类型和“显示已忽略”的必要连接。技术表格的文件名表头与各自文件列对应，文件版本在列内水平、垂直居中；列表模式的资源版本列使用相同对齐方式，TGI、类型与相关组保持原对齐。

未完成原因仍按结构化 Code／Stage 分类，不解析错误文字。资源退出文件的原因独立保留，不再参加资源关系卡；脚本正常模块仍可保留，已在脚本卡中展示的失败条目不重复列为独立文件卡。主要原因按影响条目数排序，平局顺序与 `ConflictProblemCategory` 一致，技术详情保留原始原因及错误码。

独立未完成项上方的状态圆点、原有组号与主要原因行使用白底；下方文件信息保留暖灰底色，直接展示文件名、路径、修改时间、大小和文件操作，不设展开箭头。多条原因在文件上方逐行展示，技术详情位于文件底色块下方并单独展开。忽略文件时连同原因和技术详情一起隐藏，显示已忽略后可恢复；编号沿用会话规则。范围问题仍使用原有可展开标题。

筛选在同类内取并集、状态和类型之间取交集，可以全部取消。筛选不修改报告事实，也不触发任何文件读取。未完成与范围问题仍在同一列表中，只有完整会话既无卡片也无问题时显示“没查出冲突不代表没有冲突”。

### WPF 投影与虚拟化

`ConflictResultSession.Replace` 调用 `PackageConflictGroupingBuilder.Prepare / Build` 和 `BuildScriptPairs`，保存原始报告、准备好的输入和共享的 Comparison／Collision 引用。`BuildVisibleRows` 接收类型视图、状态筛选、展开键快照和取消令牌，返回普通只读行数据，不创建 WPF 对象。投影快照复制展开以外的会话显示状态，展开键另行快照；Reset 清空报告、结果、忽略与展开状态。

扫描在后台完成汇总与初始投影后统一发布；后续筛选及展开投影也在后台执行，getter 只读取缓存。发布核对会话身份及递增请求号，重扫或清空来源替换会话身份并取消旧投影。展开集合只在 UI 调用路径修改，后台只读快照。异步投影任务处理取消和异常。

全部结果共用受限高度的 `ListBox`；来源使用独立的受限高度 `ListBox`。均使用 `VirtualizingStackPanel`、Recycling 和 `CanContentScroll`。展开行是集合中的兄弟项，不使用外层 ScrollViewer、嵌套长 ItemsControl 或承载所有子项的父项 StackPanel。展开图形为 16×16 矢量，放在 24×24 图标位中；展开点击区见[分组方案 v2](冲突检测分组方案-v2.md#51-收起时一行)。按钮支持键盘操作，沿用重复检测展开箭头的无焦点方框展示，点击或聚焦后不绘制方框。展开按钮无障碍名称为「展开／收起 + 玩家标题」，结果行无障碍名称只给玩家标题；稳定展开键仅用于 AutomationId。结果组由相邻的标题／文件／原因／技术行组成，末行绘制虚点分隔线；所有子行只有一级缩进。漏斗使用 16×16 矢量与 24×24 矩形热区。

默认窗口测试共用测试专用 `WpfTestHost` 的唯一 Application 和存活 STA Dispatcher；分别打开和关闭窗口。窗口显式加载 `Assets/Sims4ModSieve.ico` 作为标题栏图标，测试项目只以链接内容项复制该现有 ICO。虚拟化测试统计实际容器、文本及所有元素，并验证滚到远处再返回的内容和展开状态。

### 扫描与会话

正式扫描依次读取 package 索引、比较候选资源内容、扫描脚本模块、复用重复扫描核对整文件大小与 SHA256。四个阶段共用冲突页启用来源快照和取消令牌，重复结果只归属冲突会话。玩家进度按阶段映射为查找资源、读取资源索引、比较资源、查找脚本、比较同名脚本、核对文件内容、整理文件组，不直接展示 Core 的完成摘要。

`ConflictStatus` 显示中文阶段名称；`ConflictProgressText` 显示该阶段真实的「完成数 / 总数」，数字取自结构化进度参数（`CompletedItems`／`TotalItems`、`CompletedResources`／`TotalResources`），不解析 Core 的 Message。总数未知或为零时清空数字，只留阶段名称，并把 `ConflictIndeterminate` 置为真；`ProgressBar.Maximum` 用独立的 `ConflictProgressMaximum`，未知时固定为 1，不冒充真实总数。进入新阶段、取消、失败、清空来源和重扫都清掉上一阶段的数字并恢复不确定态。阶段切换、取消和迟到进度仍按 generation 与当前阶段校验，旧任务的进度不能写回新会话。`ConflictPhase` 用于完成后的未完成文件／范围问题摘要及取消、失败提示，不承载进度数字。

索引读取保持并行；完成计数递增和该计数的进度发送按同一顺序执行，同阶段的完成数不得倒退。

四个底层入口取消时均抛出 `OperationCanceledException`，不返回该阶段的部分报告；当前界面在全部阶段完成并整理后统一发布结果，取消或失败不保留部分报告。扫描完成后继续使用现有的未完成文件数／范围问题数摘要。

会话联动沿用 [Agent 指南的结果会话规则](../../AGENTS.md#73-结果会话)。两种检测分别维护来源列表、勾选状态及结果。新增、移除、勾选仅影响当前检测的范围；清空范围只重置对应检测的结果。当前应用运行期间切换页面保留各自范围与会话，关闭再打开时均恢复默认勾选当前 Mods 文件夹，不恢复上次来源或勾选；未设置且未发现默认目录时范围为空。「当前 Mods 文件夹」位置仍共用并持久化，更改位置只向当前检测范围添加或启用该目录。开始新扫描替换对应检测会话，旧任务的迟到进度不能写回新会话。

| 阶段 | 结果区文案和行为 |
|---|---|
| 初始 | 尚未扫描 |
| 扫描中 | 显示当前阶段，可取消，锁定来源编辑 |
| 已取消 | 扫描已取消，不显示完整成功结论 |
| 完成有结果 | 资源／模块及独立未完成卡片 |
| 完成无结果 | 已分析范围未发现冲突；仍展示未完成项 |
| 失败 | 扫描没有完成，显示安全摘要，允许重试 |

原型提供独立的演示状态选择器。该选择器和示例标记不进入正式产品。

## 文件对汇总数据契约

文件对汇总数据层已接入基础排查结果页。Desktop 直接消费以下契约。

`PackageConflictScanReport.ResourceInventories` 为只读清单，默认空集合，保留报告原有的位置参数构造方式。每个 `PackageResourceInventory` 保存发现阶段的规范 `Path`、完整索引读取时的 `ScannedStamp`、全部索引项的 `ResourceCount` 和只读 `ResourceTypeCounts`，类型计数包含未撞号资源；旧构造不提供类型计数时该字段为 null。索引失败的 package 不进入清单；清单不保存完整索引，也不追加文件读取。

`ConflictPairSummaryBuilder` 提供两个同步方法，均接收取消令牌并返回只读列表：

- `BuildPackagePairs(PackageConflictScanReport, ResourceContentComparisonReport, CancellationToken)` 返回 `PackageConflictPairSummary`。
- `BuildScriptPairs(ScriptModuleScanReport, CancellationToken)` 返回 `ScriptConflictPairSummary`。

两类汇总均保存 `FirstPath`、`SecondPath`、差异／一致／未完成数量及对应的独立事实 `HasConfirmedDifference`、`HasConfirmedIdentical`、`HasIncomplete`；同时有一致与差异时，`IsSuspectedModVersionPair` 为真。package 使用 `DifferentResourceCount`、`IdenticalResourceCount`、`IncompleteResourceCount` 和 `Resources`；脚本使用 `DifferentModuleCount`、`IdenticalModuleCount`、`IncompleteModuleCount` 和 `Modules`。package 另有两个独立方向的 `FirstContainedInSecond`、`SecondContainedInFirst`。

`PackagePairResourceMatch.Comparison`、`ScriptPairModuleMatch.Collision` 引用原始记录，保留完整 `ContentGroups` 与 `Uncompared`，不为每个文件对复制内容组和来源列表。明细上的三个事实只描述所属文件对，不能用原始记录的全组 `Verdict` 替代它们。

### 配对与展示资格

路径按 `PathRules.Comparer` 去重，两端按路径稳定排序，不生成自身配对。相同路径的大小写拼写以 Ordinal 最小的拼写稳定表示。跨多个 TGI 或顶层脚本包仍合并为同一个无方向文件对。数量分别按不同 TGI 和大小写敏感的模块名（`StringComparer.Ordinal`）计数，不按 occurrence 累加。

每条重叠只对共同出现的两份文件判定：成功且在同一内容组为一致，成功且在不同组为差异，其中任一文件失败为未完成。第三份文件的差异或失败不传给这两份文件。差异、一致与未完成分别保留，失败不覆盖已经确认的事实。

有差异、有未完成，或已证明至少一个方向的 package 完全包含时保留文件对；仅有一致的局部重叠隐藏。脚本本阶段不证明整个归档包含，只有一致碰撞的文件对隐藏。

汇总和明细的 `Priority` 使用 `ConflictPairPriority`：有差异为 `NeedsReview`（需查看），否则有一致为 `CanOrganize`（可整理），否则为 `Incomplete`（未完成）。未完成数量独立保留。文件对先按此顺序，再按两端路径排序；明细先按此顺序，再按数值 TGI 或 Ordinal 模块名排序。该枚举只表达展示顺序，不改变现有 Verdict。

### package 完全包含的证明

对 X–Y 两个方向分别证明。旧文件对入口过滤报告 `ToolingMetadataTypes` 中的资源比较，并从完整 `ResourceCount` 扣除这些类型的索引数量，得到包含判定使用的有效资源数；原始清单和总数不变。工具类型来源见[分组方案的排除规则](冲突检测分组方案-v2.md#3-排除不参与任何计算也不显示)。报告声明工具类型却缺少某文件的完整类型数量时，不对该文件证明包含；未声明工具类型的旧报告继续使用完整资源数。

只有 X 的有效资源数大于零，且 X–Y 已确认一致的不同 TGI 数恰好等于该数量，才可能认定 X 完全被 Y 包含。有效资源总数仍包含 X 的独有资源，因此仅有撞号资源一致不能通过该证明；多个其他文件合起来覆盖 X 也不能算作某个单一 Y 包含 X。依据是现有 `LlamaLogicPackageIndexReader` 拒绝重复 TGI，每个索引项对应一个不同资源键。

证明还要求两端均有清单和对应的 `ResourceContentComparisonReport.Packages` 稳定版本：清单戳、版本的 `ScannedStamp`、`StampAfterRead` 及该文件对成功资源 occurrence 的 `PackageStamp` 必须一致。缺少证据、版本不稳定或该对有差异／未完成时不证明包含；第三份文件失败不影响证据完整的 X–Y。双方全部资源一致时，两个方向都可以成立。所有核对只使用已有报告，不重新读取或哈希文件；结论针对报告中的已读取版本，不宣称文件此后仍未变化。

构建器先从不同内容组和失败参与文件收集候选文件对。package 另按文件统计有稳定版本证据的不同重叠资源键；有效资源数未知或重叠不足的文件不展开一致配对，其余按所需 TGI 求内容一致且版本稳定的对端交集。先处理参与文件较少的 TGI，只保留当前交集，交集为空立即停止，不为所有对端累计资源键集合。同一 TGI 的重复记录先按对端并集处理，不重复计数；交集中可保留多个完整覆盖的对端。随后遍历全部比较记录，只为候选补齐明细并执行最终判定，因此后出现的差异或失败仍能保留之前的一致明细，纯一致的局部重叠不分配配对和逐条明细。展开内容继续引用原始记录。

构建器在报告遍历、候选配对内循环、排序和结果构建中检查取消，取消抛出 `OperationCanceledException`，不发布部分汇总。确需展示的大量文件对仍可能有组合规模。该层不推断生效文件、加载顺序或删除建议。

### v2 Core 分组入口

`ConflictPairSummaryBuilder.BuildGroupingPackagePairs` 先过滤排除类型和退出文件，展开全部剩余撞号文件对，包括旧入口隐藏的纯一致局部重叠。继续使用 `PackagePairResourceMatch` 的逐对事实与共享原始 Comparison；不使用旧包含证明字段替代 v2 集合关系。`BuildPackagePairs` 和 `BuildScriptPairs` 的展示资格、包含证明及排序保持原契约。

`PackageConflictGroupingBuilder.Prepare` 接收原始索引与内容报告，返回只读 `PackageConflictGroupingInput`：排除后的文件总数与资源数、文件戳、文件对、共享比较引用，以及退出文件的原始扫描问题、失败资源、无效版本和输入缺数据原因。新入口需要完整类型数量，旧报告缺失时明确报告输入缺数据；成功索引的清单数量不齐则直接拒绝 Prepare，不补读文件。`Build` 仅接收准备好的输入与参数，生成文件对关系、卡片成员、相关 TGI、各成员计数及合集内容事实；取消不发布部分结果。

排除、四种关系、计数、参数和忽略键的规则统一见[分组方案 v2](冲突检测分组方案-v2.md)，阶段间文件变化与纯重复疑似卡的展示规则见其“整文件重复与导航”一节。当前 `ConflictResultSession` 已消费新分组入口，固定使用正式默认参数。旧文件对属性继续保留用于事实检查，并排除已确认变化的路径；WPF 卡片投影使用 `PackageConflictGroupingResult`。整文件重复使用独立报告，不能由资源内容一致推出。
