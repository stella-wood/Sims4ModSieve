# Sims 4 Mod Sieve 架构概览 v4

> 2026-11-18，基于 `main` 的 f00603d（性能阶段 1 #48、CLI-1 #49 已合入）。
> 只写现在的代码是什么样。没做的功能、以后的打算写在计划类文档里，见[文档目录](../README.md)。
> 跟代码对不上时以代码为准，并改这里。

## 1. 一句话

Windows 上的《模拟人生 4》Mod 整理工具。扫描玩家的 Mods 文件夹，找出**重复文件**、**package 资源互相覆盖**和**脚本模块撞名**；玩家确认后，可以把文件**禁用**（改名加 `.off`）、**移进回收站**或**忽略**。有桌面界面和命令行两个入口，扫描逻辑共用一套。

## 2. 几条贯穿全局的原则

- **扫描只读。** 扫描任何时候都不改文件。改动只发生在玩家点了禁用、删除或忽略之后。
- **动文件前先核对。** 删除、禁用前重新读取待操作文件的文件戳（大小、修改时间、卷序列号和文件 ID）。带有扫描哈希的待删文件还实时核对整文件 SHA-256。细节见[文件操作安全](../release/file-operation-safety.md)。
- **一个文件坏了不连累别的。** 读不了、结构损坏、压缩方式不支持的文件，记成「未分析」或读取问题，其余照常出结果。
- **避开程序自己。** 程序放进 Mods 里时，扫描跳过程序自身的文件，见[程序目录保护](../release/application-directory-safety.md)。
- **评级以产品标准为准。** 每种发现属于哪一档，以[冲突评级与拆分标准](../product/冲突评级与拆分标准.md)为准，界面和 CLI 共用。

## 3. 项目分层

```text
src/
├─ Sims4ModSieve.Core/       业务逻辑，不依赖 WPF，可在 Linux 跑测试
│  ├─ Duplicates/            文件发现、整文件哈希、重复分组、建议保留、哈希并发策略
│  ├─ Conflicts/             package 候选冲突、资源内容比较、文件对汇总、v2 文件关系分组
│  ├─ Scripts/               .ts4script 模块撞名
│  ├─ Packages/              DBPF 结构预检、索引读取接口
│  ├─ Settings/              设置存储、忽略记录（界面和 CLI 共用）
│  ├─ Reporting/             重复检测的 JSON / HTML 报告
│  └─ Diagnostics/           分阶段计时
├─ Sims4ModSieve.Packages/   唯一引用 LlamaLogic.Packages 的地方：读 package 索引、读资源内容算哈希
├─ Sims4ModSieve.Caching/    SQLite 整文件与资源哈希存储及扫描缓存包装
├─ Sims4ModSieve.FileOperations/  Windows 禁用、恢复、回收站操作与文件管理记录
├─ Sims4ModSieve.Desktop/    WPF 界面：页面（*.xaml）、ViewModels/、Services/
└─ Sims4ModSieve.Cli/        命令行：扫描、报告与文件操作
eng/
├─ Sims4ModSieve.Benchmarks/ 性能基准工具（开发用，不随产品发布）
└─ *.ps1、installer/         打包、安装包、包检查脚本
```

依赖方向：Desktop、Cli、Benchmarks → Core；读 package 内容的具体实现在 Packages，Core 只认接口（`IPackageIndexReader`、`IResourceContentHasher`）。

Desktop 和 CLI 都引用只面向 Windows 的 FileOperations；它复用 Core 的文件身份和哈希核对。CLI 直接通过这个项目操作文件。

FileOperations 通过 Windows Shell 逐项回收文件，回收前检查文件所在卷的设置。见[文件操作核对规则](../release/file-operation-safety.md)。

桌面程序、CLI 和基准工具引用 Caching。Caching 复用 Core 的 `IStableFileHasher` 和文件戳，集中使用 Microsoft.Data.Sqlite。扫描的暂存、提交和回退见[缓存项目说明](../../src/Sims4ModSieve.Caching/README.md)。

## 4. 三条扫描流水线

三条都从同一个**文件发现**入口开始（`Core/Duplicates/SourceFileDiscovery`）：把玩家给的文件夹规范化、去掉重叠、跳过程序自身文件，列出要扫的文件和它们的戳。

### 4.1 重复文件（`DuplicateScanner`）

```text
发现文件 → 按大小初筛 → 算整文件 SHA-256 → 哈希相同的归成一组 → 标出建议保留哪份
```

- 只有大小相同的文件才去算哈希，大小独一份的直接跳过。
- 算哈希的并发数按硬盘类型选（性能阶段 1，`DuplicateHashConcurrencyPolicy`）：机械硬盘 1 路，确认全是固态 4 路，判断不出来 2 路。玩家也能在设置里手动选 1/2/4/8。硬盘类型由桌面端、CLI 和基准工具链接的同一份 `WindowsStorageProfile` 判断。
- 建议保留规则见 [AGENTS.md 第 7 节](../../AGENTS.md)。

### 4.2 package 资源冲突（`PackageConflictScanner` → `ResourceContentComparer` → 分组）

```text
发现 .package → 结构预检 → 读索引 → 按资源编号（TGI）倒排，找出被多个文件共有的资源
             → 读这些资源的内容算哈希，分出「内容相同」和「内容不同」
             → 按文件对汇总 → v2 文件关系分组 → 卡片
```

- **结构预检**（`PackagePrechecker`）先挡掉明显坏掉的文件，坏文件进「未分析」。
- **读索引**是并发的；结果按排好序的位置写回，读的先后不影响结果。
- Desktop 和 CLI 开始扫描时创建 `ConflictScanOptions`，索引发现文件后、内容建立 package 批次后，分别按实际参与目录解析并发。`ScanConcurrencyDecision` 在 worker 启动前记录请求与采用值；CLI 同时写标准错误。完整策略、低层调用兼容和有限预算规则见[自动并发](性能优化与缓存架构.md#41-自动并发)。
- **资源内容**目前支持未压缩和 zlib；RefPack 压缩的资源返回「不支持」，记成未分析，不当成冲突。
- **v2 文件关系分组**把文件对归成几类：资源覆盖冲突、疑似同一 mod、合集包含、整文件重复等。规则见[冲突检测分组方案 v2](../design/冲突检测分组方案-v2.md)。

### 4.3 脚本模块撞名（`ScriptModuleScanner`）

```text
发现 .ts4script（zip）→ 列出里面的 Python 模块 → 同名模块在多个文件里出现 → 比内容，相同 / 不同分开
```

一个压缩包里有损坏条目时，只把那一条记成问题，同一包里正常的模块照常比。

### 4.4 结果怎么出

- 桌面端：冲突页把 4.2 和 4.3 的结果合成卡片，见[冲突检测页面方案](../design/冲突检测页面方案-v1.md)；重复页按组列出。
- 共用的分组函数在 `Core/Conflicts/ConflictResultGrouping`，CLI 和界面用它得到同样的组。
- 每次扫描的结果只留在这一次运行里（「结果会话」），切页面保留，重启就没了。

## 5. 文件操作

都在桌面端的 `Services/` 里，只在玩家确认后执行。

| 操作 | 怎么做 | 记在哪 |
|---|---|---|
| 禁用 | 文件改名加 `.off`，游戏就不读它了；恢复时去掉 `.off` | `disabled-mods.json` |
| 删除 | 移进 Windows 回收站（不直接删），可以撤回 | `file-management.json`（长期回收站历史） |
| 忽略 | 不改文件，只记下来，以后结果里标成已忽略 | `file-management.json` |

冲突页所有卡片与重复页的删除、禁用动作前，先检查所选文件所在完整卡片或组的成员是否存在；缺失时通知后刷新，移除缺失路径及不足两个文件的卡片，并同步选择，再对剩余待操作文件弹原确认框，详见[结果成员存在检查](性能优化与缓存架构.md#7-删除禁用前的结果成员存在检查)。待操作文件仍按第 2 节重新核对文件戳。批量操作时，一个文件失败不影响其他文件，失败的列出来给玩家看。

冲突页在删除的成员检查开始前记录列表位置，检查刷新了列表时以新结果为准重新记录。删除后的恢复方式见[分组方案 v2](../design/冲突检测分组方案-v2.md#删除撤回和缓存更新)。

## 6. 数据存放

都在 `%LOCALAPPDATA%\Sims4ModSieve\` 下：

| 文件 | 存什么 | 谁在用 |
|---|---|---|
| `duplicate-settings.json` | 默认 Mods、Tray 文件夹、哈希并发档位 | 界面、CLI（`Core/Settings/DuplicateSettingsStore`） |
| `file-management.json` | 忽略名单、回收站历史、最近一批删除的记录 ID | 界面、CLI |
| `disabled-mods.json` | 已禁用的文件 | 界面、CLI |
| `.file-management.lock` | 串行执行文件操作及回收站历史、禁用账本和忽略名单的读改写 | 界面、CLI |
| `cli-file-operations.jsonl` | 文件操作 `--apply` 记录 | CLI |
| `cache/sha256.sqlite3` | 整文件 SHA-256 | 界面、CLI |
| `application.lock` | 单实例锁 | 界面、安装器，见[运行锁](../release/application-lifecycle.md) |
| `application*.log`、`*-error.log` | 运行日志、错误日志 | 界面 |
| `scan-performance-latest.log` | 最近一次扫描分阶段计时 | 界面，见[扫描性能计时](扫描性能计时.md) |

设置写入时先写临时文件再替换，界面和 CLI 改设置都是「读最新的、只改自己那一项、写回」，互相不会冲掉对方的改动。

文件管理锁由 Windows 在持锁进程退出时释放，磁盘上可保留锁文件。文件操作开始时读取当前账本或删除历史，检测页的撤回沿用本次会话最近删除。CLI 撤回按共享记录的最近一个删除批次选取，旧记录按删除时间识别该批次。

整文件和 package 资源内容的哈希可跨扫描复用，见[缓存项目说明](../../src/Sims4ModSieve.Caching/README.md)。提交时按[实际枚举范围](性能优化与缓存架构.md#67-范围清理与禁用)清理已失效记录，也可在[常规设置的「扫描性能」](../design/设置页面方案-v1.md#缓存)主动清除。扫描结果和来源勾选留在当次运行的会话中。

## 7. 命令行（CLI）

`Sims4ModSieve.Cli.exe`，随安装包和便携包一起发，自带运行环境。

| 命令 | 干什么 |
|---|---|
| `scan-duplicates` | 查重复 |
| `scan-conflicts` | 查 package 资源冲突和脚本撞名 |
| `scan-scripts` | 只查脚本撞名 |
| `find-mods` | 找 Mods 文件夹在哪 |
| `config show` / `config set-mods` | 看设置、改默认 Mods |
| `list-disabled` / `disable` / `restore` | 查看、禁用或恢复 Mod |
| `recycle` / `undo` | 移入 Windows 回收站或撤回最近一批删除 |
| `guide` | 打印给 AI 看的说明（同仓库根目录 [AI-GUIDE.md](../../AI-GUIDE.md)） |

- 文件操作默认为预览，确认后加 `--apply`，见 [AI 指南](../../AI-GUIDE.md#禁用恢复或把文件移入回收站)和[文件操作的扫描快照核对](../release/file-operation-safety.md)。
- `--json -` 输出 JSON 到标准输出，摘要和提示走标准错误。
- 两个检测结果页与 CLI 的 `--path-contains` 共用 Core 的 `PathSearch`，按可见文件路径筛选和排序并保留整组。桌面也使用它定位原文中的高亮范围，组数跟随当前结果列表的第一项，随列表一起滚动。参数及完整汇总规则见 [AI 指南](../../AI-GUIDE.md#按需缩小报告明细)。
- `--no-cache` 跳过整文件和资源哈希缓存读写。
- 退出码：`0` 成功或无发现，`1` 有发现、未分析项或读取失败，`2` 参数错误或没有可扫描的目录，`3` 文件操作全部或部分失败。
- 不写目录时用设置里的默认 Mods。
- 结果很多时 AI 读不全的问题见 issue #50。

## 8. 安装与更新

- 发布物：Windows x64 安装包（Inno Setup）和它的 SHA-256。便携包是历史版本，以后不再发。
- 默认装到 `%LOCALAPPDATA%\Programs\Sims4ModSieve`。
- 程序启动后在后台查一次 GitHub Releases，有新版才在首页右下角显示图标；点了以后下载安装包、核对 SHA-256、交给安装器、重启。
- 版本号只在 `Directory.Build.props` 里维护。
- 流程见[安装与更新方案](../release/安装与更新方案.md)、[安装版发布流程](../release/安装版发布流程.md)。

## 9. 测试与 CI

| 测试项目 | 测什么 | 在哪跑 |
|---|---|---|
| `Sims4ModSieve.Core.Tests` | 扫描逻辑 | 哪都能跑 |
| `Sims4ModSieve.Packages.Tests` | 读 package、CLI 冲突报告、真实样本测试（默认跳过） | Windows |
| `Sims4ModSieve.Desktop.Tests` | 界面、服务、CLI | 只能 Windows（WPF） |
| `Sims4ModSieve.Benchmarks.Tests` | 基准工具 | 哪都能跑 |
| `Sims4ModSieve.Caching.Tests` | 整文件哈希存储、提交 / 取消 / 崩溃、版本失效、坏库降级 | 哪都能跑 |

CI（`.github/workflows/ci.yml`）在 Windows 上：还原依赖 → 漏洞检查 → 编译 → 全部测试 → 打安装包并试装 → 上传安装包和调试符号。真实样本测试要设 `SIMS4_MOD_SIEVE_REAL_MODS` 才跑，见 [AGENTS.md](../../AGENTS.md)。
