# 扫描性能计时

桌面端重复检测与冲突检测默认启用 `Stopwatch` 分阶段计时，只观测原有流程，不修改扫描请求、并发、预算、检测报告或筛选规则。CLI 不创建计时会话。

每次扫描结束后，在原有工具日志目录 `%LOCALAPPDATA%/Sims4ModSieve/` 中向 `application.log` 追加一份汇总。按 UTF-8 字节数计算，向非空文件追加后将超过 2 MiB（2,097,152 字节）时，先将 `application.1.log` 移为 `application.2.log` 并覆盖最老一份，再将 `application.log` 移为 `application.1.log`，本次汇总写入新的 `application.log`；最多保留这三份，单次汇总保持完整。轮转和追加共用现有写入锁。

原有 `application-error.log`、`startup-error.log` 继续只存错误。`scan-performance-latest.log` 仍覆盖保存最近结束的一次汇总，不参与轮转；重启后仍能在「设置 → 诊断与反馈 → 最近一次扫描计时」查看，点击「复制扫描计时」复制全文。标题旁的文件夹图标可打开日志目录。

## 阶段

重复检测按原顺序记录：枚举目录与文件信息 → 按长度筛选哈希候选 → 整文件 SHA-256 → 分组与报告 → 界面结果模型 → 结果绑定、首屏布局和绘制提交。

冲突检测按原顺序记录：

1. Package：枚举与文件信息、排序与读取索引、TGI 分组与索引报告。
2. 资源内容：构建按 package 的读取批次、复核索引及读取/解压/哈希、按哈希比较与分组报告。内容读取器复核索引与解压交错执行，保留在同一阶段，没有再次读取文件来拆计时。
3. 脚本：枚举与文件信息、ZIP 目录及模块读取/解压/哈希、模块名比较与分组报告。每个归档仍只打开一次，模块候选回退保持原样。
4. 整文件重复核对：复用重复扫描器的四个后台阶段；这是原有冲突流程的一部分，日志中单独列出，包含再次枚举目录的成本。
5. 冲突会话和可见行生成、扫描期间筛选的补充投影（发生时）、界面结果绑定与首屏布局/绘制提交。

UI 阶段从发布结果前开始，到 WPF Dispatcher 的 `ContextIdle` 回调结束，包含此前 `Render` 优先级的首屏布局与绘制提交。虚拟化列表中尚未进入视口的行不强制创建，后续滚动和 GPU 完成时间不在此口径内。没有可见窗口时记录「结果绑定（无可见窗口，未测渲染）」。

## 数量和耗时口径

- 总耗时为扫描开始到首次结果展示后的墙钟耗时，不包含写入本次汇总。各阶段比例均除以该总耗时；阶段外调度、进度切换和收尾单独列出。并行工作的阶段只计整个阶段的墙钟时间，不把各工作线程时间相加。
- 每个阶段记文件数、涉及文件的总长度、资源/模块条目数、读取条目数、解压尝试/成功数、未进入解压数、跳过文件数、未完成条目数、结果项数及配置并发上限。没有对应工作的计数为 0。并发上限不是观测到的线程峰值。
- 顶部扫描范围取整文件核对的枚举结果，因此冲突流程多次枚举不会重复累计范围大小。package 的索引资源总量与实际进入候选比较的资源数量分别记录；非候选资源不读取内容。
- 输入字节为涉及文件的长度，不是实际磁盘 IO。整文件阶段的处理字节为成功哈希的文件长度；资源和脚本阶段沿用原有预算消耗：package 计存储输入与解压输出之和，脚本计模块输出字节，失败前的消耗也计入。
- Package 的资源数量为索引条目数，候选内容数量为去重后的路径/文件版本/ordinal 数量。脚本读取阶段的条目数为 ZIP 目录的全部条目，读取/解压计数只在实际模块内容路径上递增；候选回退可读取多个条目。
- 解压尝试只在实际进入支持的压缩读取路径时增加，解压成功只在该条完整读取、校验通过后增加；损坏或取消可能有尝试而无成功。未压缩资源不计入解压，提前拒绝的压缩类型或超限条目也不计入尝试。「未进入解压」为内容阶段的条目总量减去解压尝试，包含未压缩、非模块及提前跳过的条目；「未完成条目」另记结果失败数量，两者可重叠。
- 当前实现没有原始字节相同就省略解压的捷径，该项始终为 0，不新增此优化。
- 记录逻辑 CPU 数、CPU 标识、OS、进程架构和来源卷的寻道惩罚查询结果。Windows 驱动能回答时显示「无寻道惩罚（通常为 SSD）」或「有寻道惩罚（通常为 HDD）」；无法查询、网络卷等情况为未知，不据此调整并发。
- 取消、异常及结果被替换的扫描也保留已结束/被中断阶段的耗时，标记未完成状态。中断时尚未汇齐的数量不能当作完整扫描规模。

计时上下文通过 `AsyncLocal` 随执行上下文传递，每个阶段一个 `Stopwatch`；并发读取只增加内存中的原子计数。阶段结束保存内存快照，每次扫描收尾统一写日志，不在逐文件、逐资源或逐数据块路径写日志。读取最近汇总最多 65536 字符，显示和复制脱敏；写入失败保留本次内存汇总并给出提示，扫描结果仍正常发布。
