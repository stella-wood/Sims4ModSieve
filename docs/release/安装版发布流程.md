# Windows x64 安装版发布流程

发布方式与更新交互以 [安装与更新方案](安装与更新方案.md) 为准。

## 构建

使用 PowerShell 7 和 [global.json](../../global.json) 固定的 SDK：

```powershell
pwsh -NoProfile -File .\eng\package-installer.ps1
```

脚本从 Desktop 项目读取最终 `Version`，调用原有 `package-portable.ps1 -SkipArchive` 生成自包含发布目录，再编译安装包。内部继续使用原发布 profile、目录命名和 [bundle 检查](../../eng/verify-portable-bundle.ps1)，不另外发布便携 ZIP。依赖锁定、运行时布局与许可证的既有约束见 [便携版发布流程](便携版发布流程.md)。

产物为 `artifacts/release/Sims4ModSieve-<版本>-setup.exe` 与 `.exe.sha256`。校验文件仅含安装包 SHA-256 的 64 位十六进制值和换行。需要复用已生成目录时传入 `-UseExistingPublish`，该选项仍会检查 bundle，但不重复发布和漏洞查询。

`install-inno-setup.ps1` 将固定的 Inno Setup 7.1.1 x64 安装到仓库 `.tools/inno-setup/compiler`，校验上游安装器 SHA-256 与 Pyrsys B.V. 的有效签名。安装编译工具会创建用户级卸载登记；产品安装本身仍为普通用户安装。中文向导直接使用该固定版本附带的 `Languages/ChineseSimplified.isl`，来源与许可见 [第三方通知](../../THIRD-PARTY-NOTICES.md)。

## 安装与更新交接

安装脚本是 [Sims4ModSieve.iss](../../eng/installer/Sims4ModSieve.iss)。固定 AppId 用于识别同一安装，Inno 保存安装位置和快捷方式选择。应用内更新只接受当前仓库最新正式 Release 中、与版本精确匹配的安装包和校验文件；下载允许 GitHub 的发布资产重定向，拒绝其他主机与非 HTTPS 下载。

更新器按声明大小流式下载、核对 SHA-256。启动前再次核对 SHA-256、安装包版本与当前用户的安装登记。它先启动完整安装包，收到交接就绪信息后确认交接，再正常关闭工具。安装包在确认交接前打开原进程的同步句柄，等待该进程完全退出后，再持有同一 `application.lock` 独占文件锁；安装期间不能启动第二个工具实例，更新完成释放锁后重新运行工具。交接超时不强制终止工具或覆盖运行中的程序。

安装器通过临时解包的程序执行只读路径检查；卸载器通过尚未移除的程序执行只读禁用记录检查。检查入口在创建窗口、获取应用运行锁和检查更新之前退出，不读取检测会话、不修改禁用记录。

临时更新包位于系统临时目录中的独立 `Sims4ModSieve-update-<随机值>` 文件夹。取消或失败会清理未完成下载，关闭尚未交接的更新也会清理；成功交接后的安装包由系统临时文件清理处理。

## CI 与本地验证

CI 在还原、漏洞检查、Release 构建与测试后执行安装包构建、bundle 检查和安装器临时目录测试，上传安装包、哈希与漏洞报告。调试符号单独上传。CI 不创建 Tag 或 GitHub Release。

```powershell
pwsh -NoProfile -File .\eng\test-portable-bundle.ps1 -SkipArchive
pwsh -NoProfile -File .\eng\test-installer.ps1
```

安装器测试使用独立测试 AppId、`artifacts/installer-tests/` 下的程序、数据与快捷方式目录，不触及真实 Mods 或产品安装；测试包不执行安装后的正常程序启动。快捷方式通过 Windows Unicode Shell Link 接口核对目标，覆盖中文和空格路径。日志保留供排查。

在本地交互桌面还可运行 `eng/test-installer-ui.ps1 -TestDirectory <上述测试输出目录>`：实际打开中文向导，取消安装，再验证卸载时明确选择删除数据及遇到目录链接时保留外部文件。此脚本只接受隔离测试包，截图保存在 `artifacts/installer-review/`。

发布时将安装包与对应 `.exe.sha256` 同时上传到同一个 GitHub Release；缺少任一资产时应用不会执行更新。若以后接入代码签名，需要先签程序 EXE 再打包，再签安装包，最后计算下载校验值。

首次及再次启动、真实跨版本覆盖升级、卸载和重新启动仍须在干净 Windows 10／11 x64 普通用户环境实际执行并记录结果。本地开发机和隔离测试包不能作为这些环境已验证的依据。
