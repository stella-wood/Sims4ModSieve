# 文件操作的扫描快照核对

重复检测的扫描快照包含文件长度、UTC 修改时间、Windows 卷序列号与文件 ID，以及整个文件的 SHA-256。操作候选继承所在重复组的哈希。确认前预检核对文件戳与身份。执行删除或禁用时，带哈希的候选用 `StableFileHasher` 实时读取内容核对 SHA-256。最后一次文件戳及身份核对在改名前或提交回收站批次前执行。单个候选失败时拒绝该文件并报告，其他通过的文件继续操作。

冲突结果行的禁用和删除携带原扫描文件戳与身份；重复文件卡片还提供重复组哈希。手动添加的禁用文件在禁用时采集身份；禁用记录保存该身份，改名后的 `.off` 文件在恢复或移入回收站前必须与记录匹配。旧禁用记录缺少身份时保留记录，拒绝自动恢复及删除，提示人工核对文件与记录。

冲突页批量删除或禁用时，同一路径同时出现在重复文件卡和其他卡片时，采用重复组的文件戳及哈希。重复检测按建议选择删除时，执行前对每组建议保留的文件实时核对一次整文件哈希，并记录读取成功时的文件戳。全部哈希核对完成后，在提交回收站前再核对保留副本的文件戳。内容对不上、文件戳变化或无法核对时跳过该组、提示重新扫描，其他组继续处理。手动勾选整组仍可执行。取舍见[决策 0011](../decisions/0011-按建议删除时复核保留文件.md)。

处理旧禁用记录时，先关闭应用，备份 `disabled-mods.json` 和对应 `.off` 文件到工具管理目录之外；依据可信备份或用户自己的 Mod 来源核对内容，并检查原路径无同名文件。确认后从备份副本手动恢复所需文件，再清理已备份清单中的对应旧记录。工具不会用当前路径新采集的 ID 补写旧记录，因为无法证明它仍是当初被禁用的文件。

只读扫描在文件系统不提供稳定文件 ID 时仍可继续，文件动作则拒绝缺少身份的候选。重解析点不会参与文件身份核对与文件动作。身份读取或内容读取出错时，对对应文件保守失败。

Windows 回收站适配器和文件改名仍按路径执行；最后一次核对与系统实际动作之间存在竞态。当前核对缩短该窗口，但不能保证路径上的对象在此期间绝不被其他进程替换。

撤回和长期回收站恢复逐项执行；每个成功项立即从历史和最近一次撤回集合中移除并保存。后续项发生预期 IO 错误时只报告该项；已完成部分遇到取消时返回完成列表和剩余未恢复列表。开始前取消直接传播。
