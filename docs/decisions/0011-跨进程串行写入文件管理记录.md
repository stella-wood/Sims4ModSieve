# 0011 跨进程串行写入文件管理记录

状态：已采纳
日期：2026-11-21

## 背景

桌面和 CLI 共用禁用账本和回收站记录。两个进程同时从旧内容读改写，即使各自用临时文件原子替换，也可能覆盖另一方的记录。玩家可能因此无法用 Sieve 恢复禁用文件，或无法定位原本可撤回的删除记录。严重度 4、发生度 3、难挽回 4，乘积 48。

## 决定

用数据目录下的 `.file-management.lock` 串行执行相关文件操作，从读取记录一直到操作结果写回。锁用 Windows 文件共享模式取得，持有进程退出时由系统释放。只读预览和 `list-disabled` 读取当时的快照，账本整理可在内存中完成。

## 比过的方案

只锁写入仍允许两个进程在同一份旧账本基础上修改。只做按记录合并也无法保护禁用预记账、改名和回收完成的顺序。覆盖整个操作可让另一方在拿到锁后，从最新账本继续。

## 代价

回收时校验哈希的时间计入持锁时间。另一方短暂等待后仍未拿到锁时会报告忙，可以稍后重试。只读结果可能在实际执行前过时。
