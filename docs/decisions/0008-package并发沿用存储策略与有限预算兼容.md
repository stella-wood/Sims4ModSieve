# 0008 package 并发沿用存储策略与有限预算兼容

状态：已采纳
日期：2026-11-19

## 背景

索引与内容阶段已有有界 worker 和稳定归并，但生产入口分别依赖底层默认值。调用入口尚不知道哪些根实际参与读取；有限内容预算本来会受任务调度顺序影响。

## 决定

统一使用扫描开始时的不可变选项快照；在现有发现或合批结束后解析并发，不新增准备接口、不重复枚举。策略与兼容契约集中见[自动并发](../architecture/性能优化与缓存架构.md#41-自动并发)。

## 比过的方案

- 入口直接按全部勾选来源定整数：会把没有 package 或内容候选的硬盘算进去。
- 新增准备流程或重复枚举：扩大阶段 2 范围，还可能让两次文件清单不一致。
- 有限预算也提高并发：会改变竞争额度的任务集合，不能作为纯性能修改处理。

## 代价

底层请求同时保留旧调用兼容和可选快照。有限预算即使手动选 8 也可能采用调用者原值，必须记录原因。Windows 真盘收益、内存峰值与 WPF 外观仍需在 Windows 验证。
