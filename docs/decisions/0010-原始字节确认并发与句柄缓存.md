# 0010 原始字节确认并发与句柄缓存

状态：已采纳，补充 0009 的确认调度与句柄约束
日期：2026-11-20

## 背景

真实 Windows A/B 中，默认关闭的复用路径省了解压却显著变慢。代码中确认串行、逐对重开两侧文件、反复读取文件戳；Windows 文件打开和安全软件检查会放大这些成本。

## 决定

按 metadata/摘要组有界并发，组内固定顺序选择直接代表；文件戳在确认阶段开始/结束复核，失败后统一撤销。共享按包有界的只读随机访问句柄缓存，不为每个句柄配置普通读取器的预读缓冲。限额、预算分配和发布规则集中见[架构第 5 节](../architecture/性能优化与缓存架构.md#52-压缩数据相同的代表复用)。

允许并发 1 保留多个空闲句柄。parallelism 约束的是同时读取的 worker，额外空闲只读句柄不增加同时磁盘读取，也不提供复用授权。正确性来自固定扫描戳、完整字节确认、代表的原 reader 验证、阶段末及发布前撤销；不来自只保留一个句柄。

## 比过的方案

- 每次比较新开文件：打开次数随资源比较数增长，Windows 上代价过高。
- 每 worker 一份永久包缓存：多个 worker 重复打开同包；共享缓存可以把缓存容量内的打开次数降到包数。
- 所有包句柄永久保留：大来源会耗尽句柄；使用有界缓存并允许安全淘汰。
- 共享可 Seek 的流但不互斥：两个组可能互相覆盖游标；每包单独保护一次块读取，一次只借一个句柄，避免互相等待两侧锁。
- worker 从全局字节额度抢占：限额命中时，完成顺序会改变哪些组获得复用；先固定分配额度。
- 确认一对就发布：失稳代表会留下过时成员；保留阶段屏障和最终统一撤销。

## 代价

确认最多使用每 worker 两块 64 KiB 工作缓冲，另有有界句柄与每包锁。淘汰空闲句柄后可能重开文件，诊断记录实际次数。单一大摘要组仍在组内顺序比较。限额遇到碰撞/短路时可能留有未用额度，但不会随并发度改变额度归属。Windows 真机收益仍需相同来源的完整快照 A/B 验证，默认 Off 不变。
