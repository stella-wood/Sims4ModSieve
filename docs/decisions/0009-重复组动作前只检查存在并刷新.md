# 0009 重复组动作前只检查成员存在，结果过时提示刷新

状态：已采纳
日期：2026-11-20

## 决定

按产品决定，删除、禁用整文件重复组成员前只检查涉及完整会话组的成员是否存在。缺失时先提示，确认后刷新结果和选择，剩余选择继续原操作。流程以[架构第 7 节](../architecture/性能优化与缓存架构.md#7-删除前的重复组实时复核)为准。

## 比过的方案

此前要求动作前实时读取全部成员内容，任一失败则整组拦截。删除进回收站可以找回，禁用可以还原；为保留成员重复读取全部内容代价高。保留副本消失说明结果过时，应刷新而不是拦人。

## 代价

不检测保留成员的大小、时间和内容变化；不保证保留副本在实际动作时仍存在。待操作文件继续走现有指纹、元数据和回收站核对，全选整组照旧允许。
