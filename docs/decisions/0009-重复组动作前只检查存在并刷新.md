# 0009 冲突页所有卡片与重复页动作前只检查成员存在，结果过时提示刷新

状态：已采纳
日期：2026-11-20

## 决定

按产品决定，冲突页所有卡片与重复页在删除、禁用动作前，只检查本次选择所在完整会话卡片或组的成员是否存在。缺失时先通知，通知关闭后按路径全局刷新，不提供拒绝刷新选项，任何类型的卡片不足两个文件即消失；选择仅保留仍属于结果的文件，仍有待操作文件才弹原确认框。流程以[架构第 7 节](../architecture/性能优化与缓存架构.md#7-删除禁用前的结果成员存在检查)为准。

## 比过的方案

此前要求动作前实时读取全部成员内容，任一失败则整组拦截。删除进回收站可以找回，禁用可以还原；为保留成员重复读取全部内容代价高。保留副本消失说明结果过时，应刷新而不是拦人。

## 代价

成员存在检查阶段只判断路径是否存在，待操作文件继续走指纹、元数据和回收站核对。按建议删除时对保留文件的执行前复核见[决策 0011](0011-按建议删除时复核保留文件.md)。
